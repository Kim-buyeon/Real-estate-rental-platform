# ci-check

**CI가 실패할 것을 미리 잡는다.** `code-reviewer`가 검토를 시작하기 전에 부른다.

## 1. 전부 돌린다

저장소가 하나이고 CI도 하나다. **바꾼 곳이 백엔드뿐이어도 프론트까지 돌린다.**

백엔드 DTO를 고치면 프론트 타입 검사가 깨진다. 연동 오류를 컴파일 시점에 잡으려고 타입을 대응시켜 둔 구조이므로, 바꾼 쪽만 돌리면 그 검증을 스스로 건너뛰게 된다.

`.github/workflows/`의 빌드·테스트 잡에 적힌 명령을 읽어 같은 순서로 실행한다. **명령을 여기에 옮겨 적지 않는다.** 워크플로가 바뀌면 이 파일이 먼저 낡고, 로컬과 CI가 다른 것을 돌리게 된다.

| 돌리는 것 | 확인하는 것 |
| --- | --- |
| 백엔드 빌드 | 컴파일 |
| 백엔드 테스트 | 단위 · 매퍼 · 통합 · 다중 인스턴스. Testcontainers가 Docker를 쓴다 |
| 마이그레이션 검증 | 통합 테스트가 Flyway부터 돈다. `ddl-auto: validate`가 스키마와 엔티티의 어긋남을 여기서 드러낸다 |
| 프론트 타입 검사 · 빌드 | 백엔드 DTO와의 계약 |
| 프론트 테스트 | SSE 전역 단일 연결 · 재연결 후 재조회 · 쿼리 무효화 연쇄 |

## 2. 인프라 파일을 건드렸으면 더 돌린다

**CI가 게이트 역할을 하지 못한다.** Nginx 설정, `prometheus.yml`, Compose 파일은 컴파일도 테스트도 되지 않아 CI가 통과해도 확인된 것이 없다 — `docs/workflow.md` 3장.

확인 명령이 그 자리를 대신한다. **대상별 명령은 `docs/git/commit-convention.md`의 표를 읽는다.** 결과는 커밋 body에 남긴다.

1장을 대신하는 것이 아니라 **더하는 것이다.**

## 3. 실패를 가른다

| 실패 | 뜻 | 다음 |
| --- | --- | --- |
| 빌드 | 컴파일이 깨졌다 | 고친다 |
| 단위 테스트 | 로직이 기대와 다르다 | 기대값 표가 맞는지 먼저 본다. `docs/architecture/testing.md` |
| 매퍼 테스트 | 컬럼명 또는 SQL 문법 | 매퍼와 스키마를 대조한다 |
| 마이그레이션 검증 | 스키마와 엔티티가 어긋난다 | 짝을 함께 커밋했는지 본다. `docs/git/commit-convention.md` |
| 다중 인스턴스 테스트 | 무상태 전제가 깨졌다 | 세션·토큰·캐시가 프로세스 메모리에 있는지 본다 |
| 프론트 타입 검사 | 백엔드와의 계약이 깨졌다 | **양쪽을 함께 본다.** 명세가 어느 쪽인지 `doc-check`가 가린다 |
| 프론트 테스트 | 연결 관리 또는 무효화 연쇄가 깨졌다 | `docs/architecture/notification.md` 1.2와 대조한다 |
| 확인 명령 | 설정이 틀렸다 | 고친다. **통과할 때까지 커밋하지 않는다** |

**초록을 만들려고 테스트를 비활성화하거나 단언을 느슨하게 바꾸지 않는다.** 실패한 테스트를 지우면 확인 수단이 사라진다.

## 4. 통과하면 넘긴다

무엇을 돌렸고 무엇이 통과했는지 알리고 `code-reviewer`로 넘긴다. **돌리지 못한 것이 있으면 그것도 적는다.** Docker가 없어 Testcontainers를 건너뛴 경우가 그렇다.

## 5. PR을 올린 뒤

로컬에서 통과했어도 CI가 실패할 수 있다.

| 무엇 | 명령 |
| --- | --- |
| 이 PR의 체크 상태 | `gh pr checks` |
| 실패한 단계의 로그만 | `gh run view <실행ID> --log-failed` |

| 상황 | 다음 |
| --- | --- |
| 로컬은 통과인데 CI가 실패 | **환경 차이를 먼저 의심한다.** Java · Node 버전, `.env` 없이 도는 설정, Testcontainers가 쓰는 Docker |
| 코드와 무관한 실패 (컨테이너 기동 시간 초과, 네트워크) | `gh run rerun <실행ID> --failed`. **한 번만.** 두 번째도 실패하면 코드 문제로 본다 |
| 재실행으로 통과 | 통과했어도 무엇이 흔들렸는지 남긴다 |
| merge 후 `develop`이 실패 | **다른 작업보다 먼저 처리한다.** 실패한 상태를 기본 브랜치에 남기지 않는다 — `docs/architecture/testing.md` 1.2. 원인이 불명확하면 그 merge를 되돌린다 |

**깨진 `develop` 위에서 다음 이슈를 시작하지 않는다.** 새 작업의 실패가 자기 것인지 앞의 것인지 구분되지 않는다.
