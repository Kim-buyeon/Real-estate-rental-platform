# kakao-map

**단계별로 무엇을 호출하고 무엇을 표시하는지는 매물 API 명세 1.2 · 1.4절이 정한다.** 이 문서는 그것을 SDK 요소로 옮긴 표다. 둘이 다르면 명세가 맞다.

## 1. 키와 도메인

| 항목 | 내용 | 어디에 |
| --- | --- | --- |
| JavaScript 키 | SDK 로드에 쓴다. 번들과 네트워크 탭에 그대로 보인다 — **비밀이 아니다.** 보호 수단은 도메인 등록이다 | `.env`의 `VITE_KAKAO_MAP_KEY` — **이름은 제안이다.** 환경 변수 목록은 `.env.example`이 갖는다(루트 `CLAUDE.md`). 거기 등록되면 확정. 코드에 값을 적지 않는다 |
| REST API 키 | 서버가 주소 · 좌표 정규화에 쓴다 (`KAKAO_REST_API_KEY`, 데이터 적재 문서 1.3) | 백엔드 `.env`. **프론트에서 쓰지 않는다** |
| 도메인 등록 | 등록된 사이트 도메인에서만 지도 API가 동작한다. 로컬 개발 주소와 운영 도메인을 모두 등록한다 | Kakao Developers 앱 설정 > 플랫폼 > Web |
| 앱 활성화 | 개발자 계정에서 **첫 번째로 활성화한 앱에만** 무료 쿼터가 붙는다. 활성화 대상을 나중에 바꿀 수 있는지는 문서에 없다 — **미검증** | 본 서비스용 앱 하나만 먼저 활성화한다 |
| 쿼터 | Web SDK 일 300,000건 | k6 부하 시험은 API만 호출하므로 여기에 잡히지 않는다 |

`VITE_` 접두 변수는 빌드 시 번들에 정적으로 치환된다. **비밀 값을 `VITE_`로 두지 않는다.**

## 2. SDK 로드

```html
<script src="//dapi.kakao.com/v2/maps/sdk.js?appkey=%VITE_KAKAO_MAP_KEY%&libraries=services"></script>
```

| 라이브러리 | 쓰는 곳 | 넣는가 |
| --- | --- | --- |
| `services` | `Geocoder` — 주소 → 좌표, 좌표 → 행정구역 | 자치구 중심 좌표를 이 방식으로 뽑기로 정하면 넣는다 (3장 미확정 ①) |
| — | SDK를 직접 쓰는 것을 전제로 썼다 | **래퍼 도입 여부는 미확정** (3장 미확정 ⑤). 래퍼로 정해지면 이 장과 5장을 고친다 |
| `clusterer` | `MarkerClusterer` | **미확정.** 7장이 정해지기 전에는 넣지 않는다 |
| `drawing` | 그리기 도구 | 넣지 않는다 |

| 규칙 | 이유 |
| --- | --- |
| `index.html`의 정적 `<script>` 태그 한 번으로 로드한다 | SPA에서 라우트가 바뀌어도 SDK는 한 번만 있으면 된다 |
| `Map`은 `window.kakao.maps`가 준비된 뒤, 컨테이너가 마운트된 뒤 만든다 | 정적 로드면 스크립트 실행 순서로 보장된다 |
| `autoload=false` + `kakao.maps.load(콜백)` 동적 로드는 **6장 확인 전에 쓰지 않는다.** 확인되면 지도 없는 화면에서 SDK를 내려받지 않으려 할 때 쓸 수 있다 | 공식 가이드 · 레퍼런스 본문에서 그 파라미터를 확인하지 못했다 |

`%VITE_KAKAO_MAP_KEY%`는 Vite가 HTML에서 치환하는 표기다. 키를 문자열로 붙여 쓰지 않는다.

## 3. 3단계 드릴다운

```
서울 전체 ──자치구 오버레이 클릭──▶ 자치구 ──마커 hover / 클릭──▶ 미리보기 카드 ──「상세 보기」──▶ 지도 옆 패널
    ▲                                 │  idle마다 표시 영역 재조회
    └──────── 되돌아가기 · 필터 유지 ────┘
```

| 단계 | 호출 | 지도 | 표시 | 상호작용 → 다음 |
| --- | --- | --- | --- | --- |
| 1 서울 전체 | `GET /api/properties/district-counts` + 필터 | 서울 25개 구가 모두 보이는 `level` — **값 미확정, 데스크톱 · 모바일 폭에서 실측**(6장). `setMaxLevel`로 그보다 축소되는 것을 막는다 | 자치구마다 `CustomOverlay` 하나 — `count`와 `gradeCounts`. **개별 마커는 그리지 않는다** | 오버레이 엘리먼트 클릭 → 2단계 |
| 2 자치구 | `GET /api/properties?district=…&minLat&maxLat&minLng&maxLng` + 필터 | `setBounds(구 경계)`로 이동 · 확대. **첫 호출은 그 뒤 첫 `idle`에서** 표시 영역을 읽어 한다 — 진입 시점에 따로 호출하지 않는다 (`idle`이 오지 않는 경우는 6장). 이후 `idle`마다 재조회 (4장) | 매물마다 `CustomOverlay` — `deposit` 억 단위 축약 + `riskGrade` 색 | hover → 미리보기 카드 (**호출 없음**, 마커 응답 값) · 클릭 → 카드 고정 · 카드 밖 클릭 → 닫힘. **포인터가 없는 환경에서는 클릭이 카드 표시다** |
| 3 매물 | `GET /api/properties/{id}` · `GET /api/properties/{id}/risk` | 그대로. 패널이 열려 지도 폭이 바뀌면 **`relayout()`** | 지도 옆 패널 | 카드의 「상세 보기」에서만 진입한다 |
| 되돌아가기 | 되돌아간 단계의 호출을 한다 | 2 → 1: `setBounds(서울 경계)` — `setLevel`만 바꾸면 중심이 자치구에 남아 서울이 다 보이지 않는다 | 오버레이를 교체한다 | **필터는 그대로다.** 필터 상태는 지도 상태와 분리해 둔다 |

**마커는 `Marker`가 아니라 `CustomOverlay`로 그린다.** `Marker` 옵션에는 이미지와 툴팁(`title`)만 있고 텍스트를 올리는 옵션이 없다. 명세가 마커에 보증금 문자와 등급 색을 요구하므로 `CustomOverlay`다. 대가가 있다 — **`CustomOverlay`에는 SDK 이벤트가 없다.** `kakao.maps.event.addListener`는 `Map` · `Marker`용이고, 오버레이의 hover · 클릭은 `content` 엘리먼트에 붙이는 DOM 리스너로 받는다 (5장).

| 3장의 미확정 | 선택지 | 정하는 곳 |
| --- | --- | --- |
| ① 자치구 25개 중심 좌표 | 상수 파일 / `services.Geocoder.addressSearch`로 한 번 뽑아 저장 | 계획 승인 |
| ② 자치구 25개 경계(남서 · 북동) | 상수 파일 / 구를 화면에 맞춰 놓고 `getBounds()`로 실측 (6장) — `Geocoder`는 점만 돌려주므로 경계는 못 뽑는다 | 계획 승인 |
| ③ 서울 전체 `level` 값과 서울 경계 좌표 | 실측 (6장) | 구현 시 `frontend/CLAUDE.md`에 기록 |
| ④ `deposit` 억 단위 축약 형식 | 소수 자릿수 · 만 단위 처리 | 계획 승인 |
| ⑤ SDK 접근 방식 | 원 SDK 직접 / 래퍼 라이브러리 | 기술 스택 정의서 4장. 이 문서는 직접 사용을 전제로 썼다 |

## 4. 표시 영역 → 쿼리 키

```
idle ──▶ map.getBounds() ──▶ sw = getSouthWest() · ne = getNorthEast()
     ──▶ { minLat: sw.getLat(), maxLat: ne.getLat(), minLng: sw.getLng(), maxLng: ne.getLng() }
     ──▶ queryKey = properties.markers({ district, ...필터, ...bbox })
```

| 규칙 | 이유 |
| --- | --- |
| 재조회 시점은 **`idle`만** | 레퍼런스: 「중심 좌표나 확대 수준이 변경되면 발생한다. 단, 애니메이션 도중에는 발생하지 않는다.」 이동 한 번에 요청 한 번이 된다 |
| `bounds_changed` · `center_changed` · `zoom_changed`로 재조회하지 않는다 | 한 번의 이동에 여러 번 발생할 수 있고, 발생 빈도가 문서에 없다 |
| 좌표는 **밖으로** 반올림한다 — `min`은 내림, `max`는 올림 | 안으로 반올림하면 가장자리 마커가 빠진다. 자릿수는 계획에서 정한다 |
| 표시 영역 좌표 · 필터 · `district`가 **전부** 쿼리 키에 들어간다 | 키에 없는 값으로 요청하면 다른 영역의 결과가 캐시에서 나온다 |
| `placeholderData`로 이전 마커를 유지한다 | 기술 스택 정의서 4장. 이동 중 지도가 비지 않는다 |
| 필터를 바꾸면 **현재 단계**의 호출만 다시 한다 | 매물 API 명세 1.2 |
| 응답 `items`가 빈 배열이면 정상이다 | 오버레이를 비운다. 오류로 다루지 않는다 |

## 5. 오버레이 만들기

| 규칙 | 이유 |
| --- | --- |
| `content`는 **엘리먼트**로 만든다. HTML 문자열에 서버 값을 이어붙이지 않는다 | `content`는 「엘리먼트 또는 HTML 문자열」을 받는다. 문자열이면 `district` 같은 서버 값이 HTML로 해석된다 |
| hover · 클릭은 `content` 엘리먼트의 DOM 리스너로 받는다 | `CustomOverlay`에는 SDK 이벤트가 없다 |
| `clickable: true` | 오버레이 안 클릭이 지도 클릭으로 새지 않는다 |
| 색은 디자인 토큰 정의서의 위험 등급 토큰 | 미분석 등급 색도 거기서. hex를 직접 적지 않는다 |
| 단계가 바뀌면 이전 오버레이를 `setMap(null)`로 지운다 | 지우지 않으면 두 단계의 오버레이가 겹친다 |
| `Map`에 붙인 `idle` 리스너는 컴포넌트 정리 시 `kakao.maps.event.removeListener`, 오버레이 엘리먼트의 DOM 리스너는 오버레이를 지울 때 함께 | 화면을 오갈 때 리스너가 누적된다 |
| 지도 컨테이너 크기가 바뀌면 `relayout()` | 패널 열림 · 창 크기 변경 뒤 타일이 어긋난다 |

## 6. 확인 전에 쓰지 않는다

| 동작 | 확인 방법 | 실패하면 |
| --- | --- | --- |
| `autoload=false` + `kakao.maps.load(콜백)` 동적 로드 | 확인 코드에서 동적 삽입 뒤 `kakao.maps.services`가 정의되는지 본다 | 2장의 정적 `<script>` 로드를 유지한다 |
| `setBounds` 뒤 `idle`이 반드시 오는가 | 이미 그 영역을 보고 있어 중심 · 레벨이 바뀌지 않을 때 `idle`이 오는지 본다 | 오지 않으면 2단계 진입 시 `getBounds()`를 한 번 직접 읽어 첫 호출을 한다 |
| `MarkerClusterer`에 `CustomOverlay`를 넣기 | `addMarkers`에 넣어 클러스터가 그려지는지 본다. 레퍼런스와 샘플은 `Marker`만 전제한다 | 클러스터 레벨은 `Marker`, 확대 뒤는 `CustomOverlay`로 이중 구현하거나 클러스터를 두지 않는다 — 7장 결정에 따른다 |
| 서울 전체 `level` · 서울 경계 · 자치구 경계 | 데스크톱 · 모바일 폭에서 25개 구가 모두 보이는 가장 확대된 레벨과 그때의 `getBounds()`. 자치구 경계도 같은 방법으로 (3장 ②) | — |

**첫 번째 작업으로 확인 코드를 만든다.** 확인 전에 그 위에 화면을 쌓지 않는다.

## 7. 착수 전 문서 확인

| 문서 | 단계 정의 |
| --- | --- |
| 서비스 기능 정의서 — 매물 PROP-02 | (1) 서울 전체 — 자치구별 매물 수 · (2) 자치구 선택 — **개별 매물 마커** · (3) 마커 선택 — 상세 |
| 매물 API 명세 1.2 | 서울 전체 → 집계 · 자치구 선택 → 매물 마커 · 매물 선택 → 상세. 클러스터 응답 엔드포인트는 없다 |
| 트래픽 정의서 3.2 | 1단계 시 전체 — 자치구 집계 · **2단계 자치구 — 동 단위 클러스터(그룹핑)** · **3단계 동 — 개별 마커(거리 계산)** |

두 가지가 갈린다. **(가)** API에는 서버가 묶어 주는 클러스터가 없다 — 「동 단위 클러스터」가 클라이언트 `MarkerClusterer`인지 서버 API 추가인지. **(나)** 트래픽 정의서의 3단계는 「동 레벨의 개별 마커」인데 이 문서 3장의 3단계는 지도 단계가 아니라 상세 패널이다 — 부하 시험의 단계 비중 30/40/30이 화면의 어느 동작에 대응하는지가 어긋난다. **둘이 정해지기 전에는 클러스터러를 넣지 않고, 3장 표는 API 명세대로 간다.**
