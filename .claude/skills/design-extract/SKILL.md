# design-extract

**참고 사이트에서 가져오는 것은 토큰과 합성 구조다.** 로고 · 브랜드명 · 문구 · 사진 · 아이콘은 가져오지 않는다. 화면은 이 진행표가 만들지 않는다 — `frontend-dev`가 정의서를 읽고 만든다.

## 1. 이 작업의 자리

문서를 만드는 작업이다. **`docs/workflow.md` 2장 순서를 밟는다** — 이슈 → 브랜치 → 계획 승인 → 이 진행표(5 · 6단계 자리) → 커밋 → `code-reviewer` → PR → merge. 1단계 `slice-start`는 문서만 만드는 작업의 갈래가 없어 건너뛰고, 읽을 것은 계획에 적는다. 계획에는 아래가 들어간다.

| 계획 항목 | 내용 |
| --- | --- |
| 슬러그 | 호스트의 주 라벨. `www.dabangapp.com` → `dabangapp` |
| 아키타입 | 우리 화면에 대응하는 참고 페이지. 예: `map-search` · `property-detail` · `login` |
| 스크린샷 | 아키타입마다 데스크톱(1440) · 모바일(560) 폭 풀페이지 각 1컷. 상태 컷(hover · focus · 열린 상태)은 있으면 |
| 프로젝트 정의 값 | 참고 사이트에 없는 토큰의 값 — 위험 등급 색 등. 사용자가 준다 |
| 정본 위치 | `DESIGN.md` · `layout.md`가 저장소에 들어갈 경로. **미확정** — 첫 계획 승인 때 정하고, `slice-start` 2장 표에 `frontend-dev` 행으로 적는다 |

캡처 방식은 **스크린샷 업로드 하나다.** 브라우저 자동화와 fetch는 쓰지 않는다 — 참고 사이트의 약관을 확인하지 않았고, 자동 접근은 승인 대상이 아니다.

## 2. 작업 폴더

저장소 루트의 `artifacts/sites/<슬러그>/`. **에이전트를 부를 때 이 경로를 넘긴다** — 에이전트는 부모 컨텍스트를 물려받지 않는다.

```
artifacts/sites/<슬러그>/
  input.md                          슬러그 · 아키타입 · 스크린샷 목록 · 진행 상태
  analysis/tokens.md                design-analyzer — 토큰 후보 · 컴포넌트 인벤토리
  analysis/merge-notes.md           델타 병합의 충돌 (있을 때만)
  examples/<아키타입>/layout.md      design-analyzer — 섹션 순서 · 그리드 · 여백 · 붕괴
  examples/<아키타입>/reference-*.png 사용자가 올린 스크린샷
  DESIGN.md                         designmd-author — 드래프트
  reviews/designmd-review.md        design-system-reviewer
```

| 규칙 | 이유 |
| --- | --- |
| 첫 실행 때 `artifacts/`를 `.gitignore`에 추가한다 (없으면) | 스크린샷은 참고 사이트의 저작물이다 |
| 이 작업이 저장소에 넣는 것은 `DESIGN.md`와 `layout.md`다 | 정본 위치는 1장. 드래프트와 정본을 두 곳에 두지 않는다 — 브랜치가 드래프트다 |
| `input.md`가 진행 상태를 갖는다 | 단계 · 산출물 · `stale` 표시 |

## 3. 모드

| 신호 | 모드 | 처리 |
| --- | --- | --- |
| 슬러그 폴더가 없다 | 초기 | 4장 전체 |
| 슬러그 폴더가 있고 새 아키타입이 들어왔다 | 확장 · 통합 | 6장. 델타만 계측해 누적 정의서에 병합 |
| 「컴포넌트만 다시」 · 「레이아웃만 다시」 | 부분 재실행 | 해당 산출물만 다시 만들고 뒷산출물을 `input.md`에 `stale`로 표시 |
| 스크린샷이 없다 | 착수 불가 | 사용자에게 요청한다. 대신 사이트를 열지 않는다 |

## 4. 순서

```
1. 입력 확정          input.md 작성. 계획 승인이 끝난 상태
        │
2. design-analyzer    tokens.md · layout.md · (merge-notes.md)
        │
3. designmd-author    DESIGN.md 드래프트 (+ 프로젝트 정의)
        │
4. design-system-reviewer   lint · A1~A5 · (A6)
        │
        ├── 불합격 ──▶ 지적받은 절만 재작업 (author 또는 analyzer) ──▶ 4로. 한 번만
        │                                                              │
        │                                          두 번째도 불합격 ──▶ best 유지, 사용자에게
        │
5. 사용자 승인        정의서 · 레이아웃 맵을 정본 위치에 둘지
        │
6. 반영               정본 위치로 복사 → 커밋 → code-reviewer → PR
```

| 단계 | 넘기는 것 | 확인 |
| --- | --- | --- |
| 2 → 3 | `tokens.md`에 값마다 「측정 / 추정」과 출처 컷이 붙어 있다 | 없는 값은 지어낸 것이다 |
| 3 → 4 | 프론트매터가 규격의 키만 쓰고, 프로젝트 정의 값이 사용자 것이다 | `designmd-spec` |
| 4 → 5 | 판정이 「합격」이거나, 「조건부」이면 남은 major가 사용자 판단 사항뿐이다 — 그 판단을 5단계에서 함께 받는다 | `reviews/designmd-review.md` |
| 5 → 6 | 사용자가 정본 위치와 덮어쓰기 여부를 승인했다 | 기존 정의서가 있으면 무엇이 바뀌는지 diff로 보인다 |

**단계 사이는 파일로 넘긴다.** 대화로만 지나간 단계는 다음 에이전트가 읽을 수 없다.

## 5. 반영

| 무엇 | 어디로 | 함께 커밋 |
| --- | --- | --- |
| `DESIGN.md` | 정본 위치 (1장) | 토큰 값을 코드로 옮긴 파일 — 위치와 형식은 `frontend/CLAUDE.md`가 정한다. 정의서만 바뀌고 코드 토큰이 안 바뀌면 둘이 어긋난다 |
| `examples/<아키타입>/layout.md` | 정본 위치의 `examples/<아키타입>/` | — |
| `reference-*.png` · `tokens.md` · `reviews/` | **커밋하지 않는다.** 작업 폴더에 남긴다 | — |

정의서와 코드 토큰 파일의 짝은 `docs/git/commit-convention.md` 짝 표에 올릴 후보다.

## 6. 확장 · 통합 — 같은 사이트에 아키타입 추가

**추가는 자동, 충돌만 사용자, 검증된 값은 덮어쓰지 않는다.**

| 관측 | 분류 | 처리 |
| --- | --- | --- |
| 기존에 없던 토큰 · 컴포넌트 | 신규 | 추가. `seen on:`에 아키타입 기록 |
| 기존과 같은 값 | 일치 | provenance만 갱신. 여러 아키타입에서 반복되면 canonical 신호 |
| 같은 역할인데 값이 다르다 | 충돌 | `merge-notes.md`에 기존값 · 신규값 · 컷. **덮어쓰지 않는다.** 변형으로 분리하거나 사용자가 고른다 |
| 팔레트 · 타이포가 전반적으로 다르다 | 발산 | 멈추고 사용자에게 — 같은 시스템에 넣을지, 다른 슬러그로 나눌지 |

| 확인 | 처리 |
| --- | --- |
| 정의서가 바뀌었다 | 코드 토큰 파일도 바뀌어야 한다 (5장 짝) |
| 새 아키타입에서 신규 토큰이 거의 없다 | 「충분히 포착됨」. 추가 계측을 멈추자고 제안한다 |
| 우리 화면이 쓰는 표준 컴포넌트 중 아직 미관측인 것이 있다 | 그것이 있을 참고 페이지를 다음 아키타입으로 제안한다 |

## 7. 하지 않는다

- **참고 사이트를 브라우저 자동화나 fetch로 열지 않는다.** 스크린샷이 없으면 요청한다.
- **페이지 · 컴포넌트 코드를 만들지 않는다.** 정의서와 레이아웃 맵까지다.
- **관측 안 된 값을 채우지 않는다.** Known Gaps에 남긴다.
- **스크린샷을 커밋하지 않는다.**
- **검수를 세 번 돌지 않는다.** 재작업은 한 번이고, 그 뒤는 사용자가 정한다.
