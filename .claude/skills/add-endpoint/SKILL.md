# add-endpoint

**명세가 계약이다.** 코드는 명세를 옮긴 것이고, 명세에 없는 경로 · 필드 · 오류 코드는 코드에도 없다. 계층별 작성 규칙은 `backend/CLAUDE.md`, 응답 봉투 · 상태 코드 · 인증 구분 · 오류 코드는 `docs/api/common.md`가 갖는다. **여기에는 값을 옮겨 적지 않는다** — 순서와 확인만 정한다.

## 1. 명세 대조표 — 코드보다 먼저

착수 시점에 올라온 영역 API 명세와 `docs/api/common.md`에서 아래를 찾아 **출처 절과 함께** 적는다. 한 칸이라도 비면 코드를 쓰지 않는다.

| 항목 | 찾는 곳 | 비면 |
| --- | --- | --- |
| 경로 · 메서드 | 영역 명세의 엔드포인트 표 | 명세에 추가를 제안한다. 임의 경로를 만들지 않는다 |
| 인증 구분 | 같은 표의 「인증」 열. 구분의 뜻은 `common.md` 1.5 | 정하지 않고 멈춘다. 기본값을 두면 공개 API가 잠기거나 보호 API가 열린다 |
| 요청 파라미터 · 본문 | 영역 명세의 파라미터 표 · 요청 예시 | 예시에서 유추하지 않는다 |
| 검증 제약 | 파라미터 표의 타입 · 범위. 페이지 크기의 기본값 · 최댓값은 `common.md` 1.4 | 제약이 없으면 없는 대로. 지어내지 않는다 |
| 응답 필드 · 형태 | 영역 명세의 응답 표 · 응답 예시. 목록이면 **커서 목록인지부터** 확인한다 — 커서 목록의 형태는 `common.md` 1.2, 커서를 쓰지 않는 목록이면 6장 | 예시에만 있고 표에 없는 필드는 명세 보완을 제안한다 |
| 성공 상태 코드 | `common.md` 1.3 | — |
| 오류 코드 | `common.md` 2장의 표 — **여기 없는 코드는 만들지 않는다** | 표에 먼저 추가를 제안한다 |
| 오류 응답 필드 | `common.md` 1.2 봉투 | 영역 명세가 봉투 밖 필드를 쓰면 두 문서가 어긋난 것이다. 알리고 멈춘다 |

표는 계획에 첨부한다. `code-reviewer`가 **2단계(계획대로 했는가)**에서 이 표와 코드를 대조한다.

## 2. 순서 — backend-dev의 6단계

`backend-dev`의 작업 순서를 그대로 쓴다. 각 단계에서 **무엇을 확인하는지**만 더한다.

```
1. 명세 확인        1장 표 + 오류 코드가 ErrorCode에 있는가
        │           스키마가 바뀌면 여기서 마이그레이션 + 엔티티
2. DTO              Request · Response · (Condition)
        │
3. 영속성           조회 → add-mapper / 변경 → Repository
        │           외부 연동이 필요하면 add-external-client로 인터페이스 + Mock을 먼저
4. Service          조회 → QueryService / 변경 → CommandService
        │           판정 · 계산이면 add-judgement
5. Controller       자원 경로 단위 클래스 + 보안 설정의 경로 규칙
        │
6. 검증             4장
```

| 단계 | 확인 | 규칙 |
| --- | --- | --- |
| 1 | 1장 표가 다 찼다. 필요한 오류 코드가 `common.md` 2장과 `ErrorCode`에 있다 — 없으면 명세 → 열거형 순서로 먼저 추가한다. 스키마가 바뀌면 마이그레이션 · 엔티티를 여기서 만든다 — 둘의 커밋 짝은 5장 | `backend/CLAUDE.md` Entity · 예외 처리 · `docs/architecture/database.md` 6장 |
| 2 | Request와 Response를 겸용하지 않았다. Response 필드명이 1장 표와 글자까지 같다. Condition은 요청 값과 조회 조건이 다를 때만. 기본값이 필요한 요청 필드는 compact 생성자가 채운다 | `backend/CLAUDE.md` DTO |
| 3 | 반환 타입으로 갈랐다 — DTO면 매퍼, 엔티티면 JPA. 외부 연동은 인터페이스와 Mock이 서비스보다 먼저 있다 | `docs/architecture/persistence.md` 1.1 · `backend-dev` 「순서가 달라지는 경우」 |
| 4 | 한쪽만 필요하면 한쪽만. 트랜잭션 경계 · 외부 호출 위치 · 판정 로직 분리는 규칙 문서대로. 예외는 `BusinessException(ErrorCode)` | `backend/CLAUDE.md` Service · 예외 처리 |
| 5 | 자원 경로 단위로 클래스를 나눴다. 응답 · 상태 코드 · 인증 사용자 · 입력 검증 처리가 규칙 문서대로. **인증 구분에 맞는 경로 규칙이 보안 설정에 들어갔다**(3장) | `backend/CLAUDE.md` Controller · `common.md` 1.5 |
| 6 | 4장 | — |

**아래에서 위로 거슬러 올라가지 않는다.** 컨트롤러를 먼저 쓰면 DTO가 컨트롤러 편의에 맞춰지고 명세에서 멀어진다.

## 3. 인증 구분 → 확인

구분의 정의는 `common.md` 1.5. 구분마다 세 자리를 확인한다.

| 자리 | 확인 |
| --- | --- |
| 보안 설정 | 새 경로가 그 구분의 매칭 규칙에 들어갔다. 「선택」은 토큰 없이 통과하되 토큰이 있으면 principal을 채운다 |
| 컨트롤러 | 「필수」 · 「관리자」는 `@AuthenticationPrincipal`로 사용자를 받는다. 요청 본문에서 사용자 식별자를 받지 않는다. 「선택」은 principal이 null일 수 있다 |
| 서비스 | 「선택」에서 개인화 필드(관심 등록 여부 등)는 principal이 있을 때만 채운다 |

「선택」을 필수로 잠그면 비로그인 매물 조회가 막히고, 공개로 두면 개인화 필드가 늘 기본값이다.

## 4. 검증

| 순서 | 무엇 | 통과 |
| --- | --- | --- |
| 1 | 컴파일 | — |
| 2 | 테스트 | 새 매퍼 · 판정에 테스트가 붙어 있다(`add-mapper` · `add-judgement`). 테스트 전략 문서가 대상으로 지목하지 않은 계층의 테스트는 만들지 않는다 |
| 3 | 기동 | Flyway 적용 뒤 `ddl-auto: validate` 통과. `validate`가 무엇까지 보는지는 문서가 정하지 않았으므로, 제약 · 길이 · 기본값은 마이그레이션과 DB 설계서를 눈으로 대조한다 |
| 4 | 예시 대조 | 명세의 요청 예시로 호출해 응답 예시와 **필드 이름 · 타입 · 중첩**을 대조한다. 값이 아니라 형태를 본다 |
| 5 | 오류 경로 | 명세가 적은 오류 상황을 하나씩 만들어 상태 코드와 `code`를 확인한다 |
| 6 | 인증 구분 | 토큰 없이 · 있으면서 · 다른 사용자 토큰으로 호출해 3장 표대로 동작한다 |

`code-reviewer`가 3단계에서 `ci-check`로 전부 다시 돌린다. 여기서 돌리는 것은 그 전에 스스로 잡는 것이다.

## 5. 함께 커밋한다

짝은 `docs/git/commit.md`의 「함께 커밋해야 하는 것」 두 표가 갖고, `git-check`가 본다. **여기에 옮겨 적지 않는다.** 엔드포인트와 트래픽 정의서 요청 조합의 반영은 그 표의 짝이면서 `doc-check`도 본다.

## 6. 멈춘다

| 상황 | 처리 |
| --- | --- |
| 1장 표에 빈 칸 | 명세 보완을 제안한다. 코드로 먼저 정하지 않는다 |
| 명세와 DB 설계서가 다르다 (필드가 있는데 컬럼이 없다, 타입이 다르다) | 어느 쪽이 맞는지 알린다. 코드에서 맞추지 않는다 |
| 영역 명세와 공통 규약이 다르다 — 오류 응답의 봉투 밖 필드, 커서 없는 목록에 건수를 담는 응답, 본문이 없는 204와 「모든 응답은 봉투」 규칙 | 어느 쪽을 고칠지 알리고 멈춘다. 정해지기 전에는 `backend/CLAUDE.md`의 예시를 따른다 |
| 상황에 맞는 오류 코드가 `common.md` 2장에 없다 (예: 토큰 없음) | 표 보완을 제안한다. 비슷한 코드를 대신 쓰지 않는다 |
| 기능이 차기 범위다 (`docs/features/overview.md` 3장) | 착수하지 않고 알린다 |
| 프론트가 이미 다른 필드명을 쓰고 있다 | 명세가 기준이다. 어느 쪽이 명세와 다른지 알린다 — `docs/conventions.md` 「정합을 유지한다」 |

## 7. 하지 않는다

- **명세에 없는 경로 · 필드 · 열거값 · 오류 코드를 만들지 않는다.**
- **컨트롤러 · 응답 · 예외 규칙을 여기서 다시 정하지 않는다.** `backend/CLAUDE.md`가 갖는다.
- **두 문서가 어긋난 것을 코드로 조정하지 않는다.** 알린다.
- **커밋하지 않는다.** 커밋은 별도 단계이며 `git-check`를 거친다.
