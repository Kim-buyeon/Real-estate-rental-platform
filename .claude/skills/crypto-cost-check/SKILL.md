# crypto-cost-check

**고르는 기준은 여기에 없다.** 후보 · 보안 하한 · 가용성 위협은 `docs/architecture/security-crypto.md`, 시험 항목과 판정(채택 · 조건부 · 탈락)은 `docs/infra/test-plan.md` 9장, 프로파일 · 요청 조합은 `docs/infra/traffic.md`, 하네스 사용법은 `chaos-harness/load/README.md` 가 갖는다. 여기서는 **순서 · 기록 · 함정**만 정한다.

## 1. 착수 전

| 확인 | 내용 |
| --- | --- |
| 후보 표 | 설계서의 후보 중 **보안 하한 이상만** 남긴다 — 하한 아래는 재지 않는다(재면 「가벼워서 좋다」는 잘못된 결론의 근거가 된다) |
| 기준선 | 바꾸기 **전**의 같은 프로파일 결과가 있는가. 없으면 기준선부터 잰다 — 전후 비교가 이 절차의 전부다 |
| 조건 고정 | 노드 · 데이터 · 스크립트 · 앞단 상한 · 앱 커밋을 적는다. 하나라도 다르면 비교가 성립하지 않는다 |
| 비용 | 인스턴스를 켜고 부하 생성기를 만들기 전에 **알리고**, 끝나면 부하 생성기는 삭제 · 노드는 정지한다 — 부하 생성기는 시험하는 동안에만 둔다(`docs/infra/system.md` 2장 LOAD-01) |

## 2. 순서

```
1. 단위 벤치마크        알고리즘 연산 하나 — 앱 슬롯과 같은 JVM · 같은 인스턴스 유형에서
        │
2. 기준선 부하          지금 구성 — 시험 계획서 9장의 해당 항목 프로파일
        │
3. 후보마다 부하        같은 프로파일 · 같은 조건
        │
4. 판정                시험 계획서 9.3
        │
5. 기록                용량 산정 리포트 절 · 설계서의 「후보」를 「확정」으로
```

| 단계 | 확인 |
| --- | --- |
| 1 | 워밍업(JIT)을 뺀 반복 측정 · 중앙값과 분포. 해싱은 한 번의 시간과 **메모리**, 서명은 서명 · 검증을 따로. 결과 단위를 적는다(µs · ms · MiB) |
| 2 · 3 | 노드별 CPU · 메모리(10초 간격 기록), 경로별 p95(해당 요청을 태그로), 포화점. DB 쪽 변화가 있으면 단계별로 초기화한 `pg_stat_statements` 스냅샷(운영 절차서 2장 「질의 통계」) |
| 4 | 보안 하한 · 포화점 감소 · p95 · **가용성 위협이 시험에서 드러났는가**(설계서 5장) — 슬롯 메모리 상한 종료, 입구 CPU 포화 등 |
| 5 | 수치 · 조건 · 회차 시각을 리포트에. 설계서의 그 행을 「확정 — 근거: 리포트 회차」로. 비용이 드는 대안이 나오면 부하 시험 결과 PDF 의 고려 사항에 |

## 3. 영역별 함정

| 영역 | 함정 | 대응 |
| --- | --- | --- |
| 비밀번호 해싱(C-1) | 기존 프로파일은 **사전 발급 토큰으로 로그인을 뺐다**(`docs/infra/traffic.md` 3.4 · 6장) — 그대로 돌리면 해싱이 측정에 안 들어간다 | 로그인 요청만으로 된 계단을 따로 만든다. 계정은 미리 가입시켜 두고 가입(해싱 1회) 비용을 섞지 않는다 |
| 비밀번호 해싱 | 앞단 IP별 상한(운영 절차서 4.2)이 로그인 몰림을 먼저 막는다 | 부하 생성기 주소가 예외인지 확인한다 — 아니면 상한 측정이 된다 |
| 비밀번호 해싱 | 이행(로그인 때 재해싱) 중에는 한 로그인이 **검증 + 새 해싱** 두 번을 한다 | 이행 중 비용과 이행 뒤 비용을 나눠 잰다 |
| HTTPS(C-2) | k6 는 keep-alive 로 연결을 재사용한다 — 핸드셰이크가 거의 안 일어난다 | 새 연결 비율을 바꾼 회차를 따로(연결 재사용 끔) — 실사용 브라우저는 그 사이다 |
| HTTPS | 부하 생성기가 사설 주소로 APP-01 에 붙으면 인증서 이름 검증이 실패한다(IP 인증서는 공인 IP) | 시험에서는 검증을 끄되 **그 사실을 기록**한다 — 운영 설정과 다른 점 |
| JWT(C-3) | 검증 비용은 요청마다지만 서명은 로그인 · 재발급 때만 | 재발급 비중을 올린 조합을 따로 — 한 회차로 두 비용을 섞지 않는다 |
| 컬럼 암호화(C-4) | 대칭 암호끼리는 차이가 오차보다 작을 수 있다(설계서 1장 가설) | 「차이 없음」도 결과다 — 억지로 순위를 매기지 않고 보안 · 운영 기준으로 고른다 |
| 컬럼 암호화 | 암호화한 컬럼이 인덱스를 잃어 **질의 계획이 바뀐** 것이 진짜 비용이다 | 알고리즘보다 먼저 질의 통계 · `EXPLAIN` 전후를 본다 |
| 공통 | 부하 중 APP-01 을 거치는 SSH 가 끊긴다(9/27 여러 번) | 기다리는 명령은 노드 안에서 `nohup` 으로 — 끊겨도 돈다 |

## 4. 하지 않는다

- **보안 하한 아래 후보를 「가볍다」는 이유로 고르지 않는다.**
- **조건이 다른 회차끼리 비교하지 않는다.** 다르면 다르다고 적고 비교에서 뺀다.
- **측정 중에 코드를 고치지 않는다.** 고치면 다음 회차는 새 기준선이다(시험 계획서 1장).
- **임시로 바꾼 것(앞단 상한 · 설정)을 남겨 두지 않는다.** 되돌린 것을 확인해 기록한다.
