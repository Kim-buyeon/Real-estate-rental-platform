# add-encrypted-column

**무엇을 · 어떤 알고리즘으로 암호화하는지는 여기서 정하지 않는다** — `docs/architecture/security-crypto.md` 4.4(대상 · 후보 · 보안 하한 · 풀어 쓰는 자리 · 키 보관)가 정하고, 확정 전이면 그 문서의 「미확정」을 따른다. 여기서는 **컬럼 하나를 안전하게 바꾸는 순서와 확인**만 정한다. 비용은 `crypto-cost-check` 로 잰다.

## 1. 착수 전 — 암호화하면 깨지는 것 표

**코드보다 먼저 채운다.** 암호문은 비교 · 정렬 · 연산 · 부분 검색이 되지 않는다. 그 컬럼을 쓰는 곳을 전부 찾는다 — 매퍼 XML · JPA 엔티티 · 리포지토리 메서드 이름 · 서비스 로직 · 배치 · 인덱스 · 제약 · 로그 마스킹 대상.

| 쓰는 곳(파일:줄) | 쓰임 | 암호화 뒤 | 대응 |
| --- | --- | --- | --- |
| | 동등 조회 · 중복 검사(예: 로그인 식별자) | 인덱스 · UNIQUE 로 못 찾는다 | **검색용 해시 컬럼**(3장) |
| | 정렬 · 범위 · 부분 검색(`LIKE`) | 안 된다 | 요구를 없애거나 암호화 대상에서 뺀다 — **설계서를 고치는 일이라 계획에서 확인받는다** |
| | DB 안 연산 · 비교(합계 · 대소 비교) | 안 된다 | 앱에서 풀어 계산하도록 옮긴다 |
| | UNIQUE · 인덱스 | 암호문마다 IV 가 달라 무의미 | 검색용 해시 컬럼으로 옮긴다 |
| | 목록 응답 | 행마다 복호화 | 목록에서 빼고 상세에서만 푸는지 계획에서 정한다 |

**표에 빈칸이 있으면 착수하지 않는다.** 대응이 「설계서를 고친다」인 행이 있으면 문서부터 고친다.

## 2. 순서

```
1. 마이그레이션 ①       암호문 컬럼(BYTEA 또는 TEXT) · 검색용 해시 컬럼 추가. 평문 컬럼은 그대로
        │
2. 변환기               JPA AttributeConverter · MyBatis TypeHandler — 같은 암호화 서비스를 부른다
        │
3. 이행                 기존 행을 앱의 일회성 이행 작업으로 암호화해 채운다
        │
4. 읽기 · 쓰기 전환      코드가 암호문 · 해시 컬럼만 쓰게
        │
5. 마이그레이션 ②       평문 컬럼 삭제 — **이행 확인 뒤 다음 배포에서**
        │
6. 테스트 · 측정         4장 · crypto-cost-check
```

| 단계 | 확인 |
| --- | --- |
| 1 | 적용된 마이그레이션은 고치지 않는다(훅이 막는다). 컬럼 이름은 `docs/conventions.md` · 데이터베이스 설계서 규칙대로. 설계서의 그 표에 컬럼을 더한다 |
| 2 | 암호화 서비스는 하나 — 알고리즘 · 키 · IV 규칙이 한 곳에만 있다. 변환기는 그것을 부르기만 한다 |
| 3 | **앱의 일회성 이행 작업**으로 채운다 — SQL 마이그레이션은 키가 없어 암호화할 수 없다(설계서 4.4). 이행 중에도 서비스가 돈다 — 두 컬럼을 함께 읽는 기간(암호문이 있으면 암호문, 없으면 평문)을 둔다 |
| 4 | 1장 표의 모든 행이 대응대로 바뀌었다 |
| 5 | 평문 컬럼을 지우기 전에 암호문 · 해시가 전 행에 있다(개수 질의로 확인). **되돌릴 수 없는 단계다** — 백업 확인 뒤 |

## 3. 검색용 해시 컬럼 · 키 — 확인만

**규칙(해시 알고리즘 · 키 분리 · 정규화 · 키 식별자 · 키 보관)은 `docs/architecture/security-crypto.md` 4.4 · 4.5 가 갖는다.** 여기서는 구현이 그것을 지켰는지 확인한다.

| 확인 | 틀렸을 때 |
| --- | --- |
| 정규화 규칙이 암호화 서비스 **한 곳**에만 있다 | 저장 때와 조회 때 정규화가 달라 조회가 조용히 실패한다 |
| 해시 키 ≠ 암호화 키, 둘 다 환경 변수(이름만 `.env.example`) | 한 키가 새면 둘 다 뚫린다 |
| UNIQUE · 인덱스를 해시 컬럼으로 옮겼다 | 중복 검사가 사라진다 |
| 암호문에 키 식별자가 붙는다 | 키 교체 때 옛 암호문을 못 푼다 |
| 키가 없거나 짧으면 **기동이 실패한다** | 조용히 평문으로 저장되는 경로가 생긴다(`JwtTokenProvider` 가 서명 키 길이를 검사하는 것과 같다) |
| 키가 로그 · 예외 메시지 · 질의에 실리지 않는다 | 로그 · 질의 통계에 키가 남는다 |

## 4. 테스트

| 확인 | 방법 |
| --- | --- |
| 왕복 | 암호화 → 복호화가 원문과 같다. 빈 문자열 · 최대 길이 · 한글 · `null` |
| 같은 평문 두 번 | 암호문이 다르다(IV 가 매번 새로) · 해시는 같다 |
| 변조 | 암호문 한 바이트를 바꾸면 복호화가 **실패한다**(인증 암호화) — 쓰레기 값을 돌려주지 않는다 |
| 다른 키 | 다른 키로는 풀리지 않는다 · 키 식별자로 옛 키를 고른다 |
| DB 에 평문이 없다 | 저장 뒤 원시 질의로 그 컬럼을 읽어 평문이 아님을 본다 |
| 1장 표의 대응 | 행마다 한 케이스 — 해시 조회 · 앱 계산 · 목록 |
| 이행 | 평문만 있는 행 · 암호문만 있는 행 · 둘 다 있는 행 |

테스트 종류와 자리는 `docs/architecture/testing.md` 를 따른다(`test-engineer`).

## 5. 함께 커밋한다

짝은 `docs/git/commit-convention.md` 「함께 커밋해야 하는 것」이 갖고 `git-check` 가 본다 — 마이그레이션 + 엔티티, 변환기 + 테스트. 컬럼을 더하면 데이터베이스 설계서의 그 표도 같은 변경에.

## 6. 하지 않는다

- **알고리즘 · 파라미터 · 대상을 여기서 정하지 않는다.** 설계서가 미확정이면 계획의 「정해야 할 것」으로 올린다.
- **암호 연산을 직접 짜지 않는다.** 표준 API(JDK `javax.crypto` 등) · 검증된 라이브러리만 — 모드 · 패딩 · IV 를 손으로 조합하지 않는다.
- **평문 컬럼을 같은 배포에서 지우지 않는다.** 이행 확인 뒤 다음 배포다.
- **로그 마스킹 대상에서 빼지 않는다.** 암호화해도 복호화한 값이 로그로 나갈 수 있다.
- **커밋하지 않는다.** 커밋은 별도 단계이며 `git-check` 를 거친다.
