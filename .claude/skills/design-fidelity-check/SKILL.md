# design-fidelity-check

**검수자는 만들지 않는다.** 판정은 수치 · 린터 출력 · 스크린샷 대조에 묶는다. 대상과 리포트는 호출 시 받은 작업 폴더(`artifacts/sites/<슬러그>/`) 아래에 있다.

## 출력 — `reviews/designmd-review.md`

```markdown
# 검수 리포트 — DESIGN.md (<슬러그>, 라운드 <n>)
판정: 합격 | 조건부 합격 | 불합격
린트: error <n> · warning <n>  (명령 출력 첨부)
## 위반 (심각도 순)
- [critical] <위치> — <무엇이> <왜 문제> → <수정 지시>
- [major] …
- [minor] …
## 통과 항목
- …
## 재실행 지시
- <author | analyzer>에게 / <어느 절만>
```

| 판정 | 기준 |
| --- | --- |
| 합격 | critical · major 0건 |
| 조건부 합격 | critical 0건이고, 남은 major가 **사용자 판단 사항만**이다 — 1회 관측 값의 채택 여부, 충돌 값 중 어느 쪽을 canonical로 둘지. 규격 위반 · 누락 · 추정의 확정값 표기 같은 **집필 결함이 major로 남아 있으면 조건부가 아니라 불합격**이다 |
| 불합격 | critical 1건 이상, 또는 집필 결함 major가 남았다 |

**라운드는 한 번 더다.** 두 번째도 불합격이면 best 버전을 유지하고 사용자에게 넘긴다.

## 순서

```
0. 린트          npx @google/design.md lint DESIGN.md
1. A1 참조       깨진 {group.token} 전수
2. A2 명암비     component마다 textColor ↔ backgroundColor
3. A3 고아       정의됐는데 참조 없는 토큰
4. A4 완성도     규격 · 커버리지 · 프로젝트 정의
5. A5 레이아웃   layout.md ↔ reference-*.png
6. A6 병합       증분 모드일 때만
7. 리포트
```

## A1 · broken-ref

| 확인 | 심각도 |
| --- | --- |
| 본문 · `components`의 모든 `{group.token}`이 프론트매터에 정의돼 있다 | 없는 참조 1건이라도 critical. 전부 나열한다 |

## A2 · contrast-ratio

| 대상 | 기준 |
| --- | --- |
| 본문 크기 텍스트 | ≥ 4.5:1 |
| 큰 텍스트 (18pt = 24px 이상, 또는 bold 14pt ≈ 18.66px 이상) | ≥ 3:1 |
| 색 블록 위 텍스트, 프로젝트 정의 색(등급 배지) 위 텍스트 | 같은 기준. **여기서 가장 자주 깨진다** |

미달 쌍은 `#000 on #dceeb1 = 1.4:1 ✗`처럼 수치와 함께 적는다. 미달은 major, 본문 텍스트가 3:1 미만이면 critical.

## A3 · orphaned-tokens

정의됐으나 `components`와 본문 어디서도 참조되지 않는 토큰. **삭제 후보로 표시한다.** 불합격 사유는 아니다(minor). 공식 린터는 색 토큰만 보므로 타이포 · 반경 · 간격은 여기서 본다.

## A4 · 완성도

| 확인 | 기준 | 심각도 |
| --- | --- | --- |
| 프론트매터 키 | 규격의 키만. 규격 밖 최상위 키가 있으면 지적 | major |
| 타이포 필드 | `designmd-spec` 1장의 필드 외 이름이 없다. 관측 안 된 필드를 채우지 않았다 | major |
| 본문 절 | 규격 8절 중 **있는 것끼리** 규격 순서대로이고, 생략한 절은 `omitted`에 있다. 규격 밖 절(Responsive · Iteration · Known Gaps)은 그 뒤에 있다 | major |
| 색 역할 명명 | 의미 기반. 보이는 색 이름이면 지적 | minor |
| 변형 · 상태 | 별도 항목으로 분리됐다 | minor |
| 표준 컴포넌트 커버리지 | `tokens.md`에 존재가 확인된 표준 컴포넌트가 `components`에 빠짐없이 있다. **없는 컴포넌트를 요구하지 않는다.** 컷이 없어 미관측인 상태는 Known Gaps에 있어야 한다 | 누락 major |
| 프로젝트 정의 | 값의 출처가 사용자다. 집필자가 정한 값이면 critical. 값이 없는 키는 없고(넣지 않는다), 미확정은 Known Gaps에 있다 | critical / major |
| Known Gaps | 추정 · 미관측 · 1회 관측이 정직하게 적혔다. `tokens.md`의 「추정」이 정의서에서 확정값처럼 적혔으면 지적 | major |
| 브랜드 요소 | 로고 · 브랜드명 · 문구 · 사진 언급 0건 | critical |

## A5 · 레이아웃 맵 대조

**`layout.md`를 스크린샷과 직접 대조한다.** `frontend-dev`가 화면을 만들 때 읽는 근거이므로, 여기서 틀리면 화면이 틀린다.

| 확인 | 어긋난 예 |
| --- | --- |
| 섹션 순서가 컷과 같다 | 컷에 있는 필터 바가 `layout.md`에 없다 |
| 섹션별 색 블록 토큰이 맞다 | 흰 배경을 `surface-soft`로 적었다 |
| 그리드 컬럼 수 · 컨테이너 폭이 맞다 | 3컬럼을 2컬럼으로 |
| 반응형 붕괴가 모바일 컷과 맞다 | 모바일에서 사라진 사이드바가 그대로 있다 |
| 여백 리듬이 근사한다 | 섹션 간격이 `section`인데 `xl`로 |

크게 어긋나면 `design-analyzer`로 회송한다. 정의서가 아니라 계측이 틀린 것이다.

## A6 · 확장 · 통합 — 증분 병합일 때만

| 확인 | 기준 |
| --- | --- |
| silent overwrite 없음 | 기존 정의서와 diff. 같은 역할의 값이 바뀌었으면 `merge-notes.md`에 충돌로 기록돼 있어야 한다 |
| 충돌이 승인 대상으로 남았다 | 변형 분리 또는 「사용자 결정」 표기 |
| provenance 갱신 | `> Source pages:`와 `seen on:`에 새 아키타입 |
| 1회 관측의 승격 없음 | 한 아키타입에서만 본 값이 canonical로 바뀌지 않았다 |
| 발산 | 서브브랜드처럼 갈리는 페이지가 억지로 병합되지 않았다 |
| 코드 토큰 파일 | 정의서가 바뀌었으면 함께 바뀌어야 하는 짝이다 — 반영 단계에서 확인 |

## 검수 태도

| 원칙 | 내용 |
| --- | --- |
| 경계는 수치다 | 4.5:1, 깨진 참조 0건, 브랜드 요소 0건. 「대체로 괜찮음」은 판정이 아니다 |
| 자기평가를 믿지 않는다 | 집필자가 「지켰다」고 적어도 산출물을 직접 본다 |
| 갈리는 항목에 집중한다 | 색 블록 위 명암비, 등급 배지 명암비, 모바일 붕괴, Don't 위반 |
| 고치지 않는다 | 결함과 지시만. 수정은 author 또는 analyzer |
| 라벨만 붙이지 않는다 | 판정마다 근거 |
