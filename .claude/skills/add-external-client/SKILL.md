# add-external-client

**외부 한 곳의 장애가 매물 조회 전체를 멈추게 하지 않는다.** 연동 대상별로 인터페이스와 세 구현을 두는 구조는 `docs/tech-stack.md` 2장(RestClient · Resilience4j)과 `backend/CLAUDE.md` 패키지 구조가, 무엇을 언제 가져오는지는 `docs/architecture/data-loading.md`가 정한다. 여기서는 순서와 확인만 정한다.

## 1. 대상 확인 — 시작 전

| 확인 | 찾는 곳 | 없으면 · 다르면 |
| --- | --- | --- |
| 이 연동이 1단계인가 | `docs/tech-stack.md` 6장 「범위」 열 | 차기면 **만들지 않는다.** 인터페이스만 미리 두지도 않는다 — `docs/conventions.md` 「미리 만들지 않는다」 |
| 사전 적재인가 요청 시점 조회인가 | `data-loading.md` 1.1 · 1.2 | 표에 없으면 문서 보완을 제안한다 |
| 환경 변수 이름 | `data-loading.md` 1.3 표 | 표에 먼저 추가하고 `.env.example`에 이름만 올린다. 코드에 값을 적지 않는다 |
| 승인 상태 | `tech-stack.md` 6장 말미 — 1일차 신청, 승인 전 Mock | 승인 전에는 Real을 붙이지 않는다 |
| Real이 있을 수 있는가 | `data-loading.md` 1.3 — 등기부등본은 「개방 API 없음 · Mock 어댑터」 | 그 대상은 **Mock만** 만든다 |

## 2. 구조

`external/<연동 대상>/` 아래 인터페이스 + Mock · Real · Fault — `backend/CLAUDE.md` 패키지 구조. **클래스 · 파일 이름 규칙은 미확정**이다. 첫 연동의 계획에서 정하고 `backend/CLAUDE.md`에 남긴다.

| 구성 | 규칙 | 근거 |
| --- | --- | --- |
| 인터페이스 | 메서드 이름은 우리 도메인 용어. 외부 응답 형태를 인터페이스에 노출하지 않는다 | `docs/conventions.md` 도메인 용어 |
| Mock | 항상 동일한 정상 응답. 네트워크 · 시각에 무관 | `docs/architecture/testing.md` 1.1 외부 연동 테스트 |
| Real | RestClient. 키 · 기본 URL은 환경 변수. 제공처 문서의 요청 형식은 코드 주석에 출처 URL과 함께 | `docs/tech-stack.md` 2장 RestClient |
| Fault | 지연 · 오류 · 타임아웃을 설정으로 고를 수 있게 | `testing.md` 1.1 |
| 응답 출처 표기 | 응답에 출처를 남길 수 있게 한다 — 명세가 `dataSource`를 요구하는 곳이 있다 | `docs/api/risk.md` 1.3 |
| 구현 선택 방식 | **미확정.** 프로필인지 설정 키인지 첫 연동의 계획에서 정하고 환경 구성에 기록한다 | — |

## 3. 격리

| 장치 | 규칙 | 근거 |
| --- | --- | --- |
| 타임아웃 | 대상마다 연결 · 읽기 타임아웃. **값 미확정** — 계획에서 정하고 설정 파일에 둔다 | `tech-stack.md` 2장 Resilience4j |
| 재시도 | 조회(멱등)만. 횟수 · 간격 **미확정** | 같음 |
| 서킷 브레이커 | 대상마다 하나. 임계값 **미확정.** 서킷 상태를 커스텀 지표로 노출한다 — 지표 이름과 카탈로그 등록은 `monitoring-engineer`와 `docs/infra/observability.md` 지표 카탈로그 소관 | `tech-stack.md` 2장 Actuator |
| 폴백 | 대상별로 정한다. **폴백이 판정 입력을 채우면 안 된다** — 대장 조회 실패를 「위반건축물 아님」으로 채우면 `business-logic.md` 2장의 조건 검사가 거짓 통과한다. 판정 불가 상태를 어떻게 표현 · 저장할지는 **미확정**(RISK_ANALYSIS의 가입 여부 컬럼은 NOT NULL 불리언이다 — 스키마 변경 여부를 첫 연동 계획에서 판단) | `database.md` RISK_ANALYSIS · `docs/api/common.md` 2장 `EXTERNAL_API_UNAVAILABLE` |
| 트랜잭션 밖 | 외부 호출을 트랜잭션 안에 두지 않는다 | `backend/CLAUDE.md` Service |
| 병렬 호출 | 매물 1건 분석의 등기 · 대장 · 시세는 동시에 — 가상 스레드 | `docs/architecture/performance.md` 1.1 · `data-loading.md` 1.2 |
| 캐시 | 같은 매물의 중복 조회를 차단한다. **TTL 미확정** — 갱신 주기는 `data-loading.md` 1.5, 「넉넉히」까지가 `performance.md` 1.1 | `tech-stack.md` 2장 Spring Cache |
| 호출량 제어 | 일일 한도 있는 공공 API의 사용량 집계와 임계 초과 시 캐시 대체는 관점이 맡는다 | `docs/architecture/spring-aop.md` 1.1 |

## 4. 관점 — 클라이언트에 반복하지 않는다

| 관점 | 클라이언트가 할 일 |
| --- | --- |
| 외부 API 호출 로깅 (요청 · 응답 · 소요 시간 · 실패 사유) | 애노테이션을 붙인다. 로깅 코드를 쓰지 않는다 |
| 호출량 제어 | 같음 |

| 규칙 | 근거 |
| --- | --- |
| 포인트컷은 애노테이션 기준. 애노테이션 이름은 **기반 작업(AOP)이 정한다** — 없으면 그 작업이 먼저다 | `spring-aop.md` 1.2 · `slice-start` 기반 작업 「설정 — AOP」 |
| 같은 클래스 내부 호출에는 관점이 걸리지 않는다. 클라이언트는 별도 빈 | `spring-aop.md` 1.2 |
| 관점의 예외가 호출 결과를 바꾸지 않는다 | 같음 |
| 키 · 토큰은 로그에 남기지 않는다. URL의 키 파라미터는 마스킹 | 로그 규약(마스킹) — `slice-start` 기반 작업 「관측」 행. 규약 자체는 아직 미작성 기반 작업이다(`docs/roadmap.md` 1주차) |

## 5. 응답 처리

규칙은 `data-loading.md` 1.4 · 1.5가 갖는다. 확인만 한다.

| 확인 | 근거 |
| --- | --- |
| 외부 응답을 그대로 저장하지 않았다 — 정규화 · 좌표 확보 뒤 우리 컬럼으로 | `data-loading.md` 1.4 |
| 적재 · 수집 시각을 함께 저장했다 | 같음 · `docs/api/property.md` 1.8 `collectedAt` |
| 실패 항목은 건너뛰고 기록했다. 중복은 자연키로 막았다 | `data-loading.md` 1.4 |
| 갱신은 성공한 항목만 반영한다 | `data-loading.md` 1.5 |
| 외부 DTO와 우리 DTO를 나눴다. 외부 필드명이 우리 응답에 새지 않는다 | `backend/CLAUDE.md` DTO |

## 6. 테스트

| 대상 | 구현 | 확인 |
| --- | --- | --- |
| 정상 경로 | Mock | 인터페이스 → 서비스 → 저장까지. 응답 정규화가 맞다 |
| 서킷 · 폴백 | Fault(오류) | 연속 실패 뒤 서킷이 열린다. 열린 동안 폴백이 나간다. 폴백이 판정 입력을 채우지 않는다 |
| 타임아웃 | Fault(지연) | 설정한 시간 안에 예외가 난다 — 기준은 설정값 + 여유 |
| 병렬 호출 | Fault(지연) 셋 | 셋을 순차로 부른 시간보다 짧다 |
| 캐시 | Mock + Redis 컨테이너 | 같은 매물 두 번 조회에 외부 호출은 한 번 |
| Real | **테스트에서 부르지 않는다** | 승인 · 쿼터 · 비용. 실연동 확인은 수동으로 한 번 하고 결과를 기록한다 |

테스트 코드에 실제 키 · 운영 URL · 운영 데이터 샘플을 넣지 않는다.

## 7. 함께 커밋한다

짝은 `docs/git/commit.md`의 표가 갖고 `git-check`가 본다. 환경 변수 이름이 `data-loading.md` 1.3 · `.env.example` · 코드 세 곳에 같아야 하는데, 이것은 커밋 짝이 아니다(경로가 scope를 넘는다) — `doc-check` 2장의 `.env.example` 행이 본다.

## 8. 멈춘다

| 상황 | 처리 |
| --- | --- |
| 대상이 차기 범위 | 만들지 않고 알린다 |
| 환경 변수 이름이 `data-loading.md` 1.3에 없다 | 문서에 먼저 추가 |
| 폴백이 판정 입력을 채우게 된다 | 설계를 멈추고 판정 불가 상태의 표현을 계획에서 정한다 |
| 관점의 애노테이션이 아직 없다 | 기반 작업(AOP)이 먼저다. 로깅을 클라이언트에 직접 쓰지 않는다 |
| 제공처 문서와 우리 명세의 필드가 다르다 | 외부 → 우리 DTO 변환에서 흡수한다. 우리 명세를 외부에 맞추지 않는다 |

## 9. 하지 않는다

- **키를 코드 · 테스트 · 문서에 적지 않는다.**
- **트랜잭션 안에서 외부를 부르지 않는다.**
- **외부 응답 형태를 우리 API 응답에 노출하지 않는다.**
- **Real을 승인 전에 붙이지 않는다.**
- **폴백으로 판정 입력을 채우지 않는다.**
- **차기 범위 연동을 미리 만들지 않는다.**
- **커밋하지 않는다.** 커밋은 별도 단계이며 `git-check`를 거친다.
