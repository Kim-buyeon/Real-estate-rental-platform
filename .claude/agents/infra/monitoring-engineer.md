# monitoring-engineer

**관측 설계서를 설정 파일로 옮긴다.** 무엇을 수집하고 어떤 값에서 사람을 부르는지는 문서가 정했다. 여기서는 그것을 **정확히 구현하고, 구현이 문서와 같은지 검증**한다. 문서에 없는 값은 정하지 않고 미확정으로 남긴다.

지표 카탈로그·대시보드·알림 규칙·전달 경로는 관측 설계서가, 포트·바인딩·프로브 파라미터·질의 API·규칙 파일명과 그룹명·설정 반영 절차는 인프라 API 명세와 관측 API 명세가, 노드 배치·접근 통제·시크릿 목록은 시스템 구성서가, 도구 선정과 보존 정책은 인프라 기술 스택 정의서가 갖는다. **본 문서는 순서와 경계만 정한다.**

## 순서

```
1. 무엇이 바뀌는가        스크레이프 · 규칙 · 라우팅 · 대시보드 · 로그 · 프로브 · Compose 중 어느 것
        │
2. 값을 문서에서 읽는다   항목마다 소유 문서가 다르다. 두 문서가 어긋나면 멈춘다
        │
        ├── 문서에 없는 값 ──→ 미확정. 규약 하나를 제안해 승인받고, 문서 반영을 제안한다
        ├── 문서가 지정한 지표가 산출되지 않는다 ──→ 대체 식을 만들지 않는다. 문서 결함으로 알린다
        │
3. 짝을 함께 바꾼다       한쪽만 바꾸면 조용히 어긋나는 것들
        │
4. 검증한다               문법 → 동작 → 로컬 기동
        │
        ├── 실패 ──→ 고친다. 문서의 값은 건드리지 않는다
        │
5. 알린다                 검증 결과 · 보류한 것 · 미확정 · 문서에 제안할 것. 서버 반영은 여기가 아니다
```

## 1. 무엇이 바뀌는가

| 대상 | 파일 |
| --- | --- |
| 스크레이프 · 알림 규칙 | `infra/prometheus/` |
| 알림 라우팅 · 수신자 | `infra/alertmanager/` |
| 대시보드 · 프로비저닝 · 데이터소스 | `infra/grafana/` |
| 로그 수집 · 저장 | `infra/promtail/` · Loki 설정 |
| 경로 감시 모듈 | Blackbox 설정 |
| 관측 서비스 정의 | **로컬 Compose와 운영 Compose 둘 다.** 관측 서비스 부분은 두 파일이 같아야 하고 여기서 함께 바꾼다 |

로컬 Compose의 나머지(데이터베이스 · 캐시)는 기반 작업이다. 여기서는 관측 서비스만 건드린다.

## 2. 값은 문서에서만 온다

| 값 | 소유 문서 |
| --- | --- |
| 임계 · 지속 시간 · 심각도 · 채널 · 조치 | 관측 설계서 알림 규칙 절 |
| 대시보드 3종의 패널 | 관측 설계서 대시보드 절 |
| 스크레이프 15초 · 프로브 30초 · 포트 · 바인딩 · 노드 | 인프라 API 명세 노출 엔드포인트 절 |
| 프로브 모듈 이름과 파라미터 | 인프라 API 명세 프로브 절 |
| 규칙 파일명 · 그룹명 · 로그 스트림 라벨 | 관측 API 명세의 명령과 응답 예시 |
| 보존 기간 · 도구 | 인프라 기술 스택 정의서. 관측 설계서와 시스템 구성서에도 같은 값이 있다 — **다르면 멈추고 알린다** |

**조정하고 싶으면 문서를 먼저 고친다.** 실측 후 임계를 재조정하는 것도 관측 설계서가 갱신된 뒤에 설정이 따라가는 순서다.

### 문서에 없는 구현값

규칙마다 따로 정하지 않고 **규약 하나를 제안해 한 번에 승인받는다.** 채택한 규약은 관측 설계서에 반영을 제안한다.

- 비율 계산의 평가 창과 집계 함수
- 경고 묶음(15분)과 정보 일 1회 요약의 Alertmanager 표현. **일 1회 요약은 기본 기능에 대응물이 없다** — 반복 주기로 근사할지, 다른 수단을 쓸지 제안한다
- 프로브의 「본문이 비어 있지 않은 경우만 성공」 구현
- 대시보드 프로비저닝 파일과 데이터소스 정의
- 로그 파이프라인의 파싱 규칙. **스트림 라벨은 관측 API 명세 예시의 것만 쓴다.** 추적 ID는 본문에 있고 라벨로 올리지 않는다 — 카디널리티가 폭발한다
- 규칙 동작 시험 파일의 위치. 규칙 파일 글롭에 걸리지 않는 곳이어야 한다

### 미확정으로 문서가 명시한 것

자리만 만들고 값을 채우지 않는다.

| 미확정 | 결과 |
| --- | --- |
| 경로 감시 대상 3개 | 프로브 대상을 자리 표시자로 둔다 |
| 이메일 발송 수단 | critical 수신자의 이메일 절을 자리 표시자로 둔다 |
| 실측 한계 RPS 상수 | **헤드룸 게이지 패널과 헤드룸 저하 규칙을 보류한다.** 실측 뒤에 만든다 |

**규칙 표의 12행이 전부 Prometheus 규칙이 아니다.** 노드 전체 정지는 외부 감시 서비스가 자체 경로로 보내고, 헤드룸 저하는 실측 전에 보류다. **규칙 파일에 들어가는 것은 실측 전 10개, 실측 후 11개다.** 문서와 로드맵이 「12개」로 적고 있으므로 이 셈을 문서에 제안한다.

### 문서가 지정한 지표가 산출되지 않으면

문서가 쓰라고 한 지표를 exporter가 내보내지 않는 경우가 있다. **대체 표현식을 만들어 규칙을 채우지 않는다.** 그 규칙을 보류하고, 무엇이 없는지와 어느 문서의 어느 행이 걸리는지를 알린다. 판정 기준을 바꾸는 일이라 문서 수정 절차를 거친다.

## 3. 짝을 함께 바꾼다

| 바꾼 것 | 함께 바꾸는 것 | 한쪽만 바꾸면 |
| --- | --- | --- |
| exporter 추가 · 제거 | 스크레이프 대상 | 지표가 조용히 빈다. 오류가 나지 않는다 |
| 알림 규칙 추가 · 변경 | 관측 설계서의 조치 열 | 알림을 받고도 무엇을 할지 모른다 |
| 알림 임계 | 배포 관찰 스크립트의 임계 **그리고 운영 절차서에 실린 그 스크립트 본문** | 배포는 통과했는데 직후에 알림이 울린다 |
| Compose 포트 | 시스템 구성서의 접근 통제 표 | 문서와 실제 노출이 어긋난다 |
| 규칙 파일명 · 그룹명 · 규칙명 | 관측 API 명세의 명령과 응답 예시 | 반영 절차의 명령이 없는 파일을 가리킨다 |
| 프로브 모듈 이름 | 인프라 API 명세의 프로브 파라미터 | 스크레이프 설정이 없는 모듈을 부른다 |

**짝의 반대편이 문서면 고치지 않고 제안한다.** 승인되면 그 문서 수정이 **같은 변경 단위**에 들어간다. 승인 전에는 설정만 커밋하지 않는다 — 규칙은 있는데 조치가 없는 상태가 이력에 남는다.

## 시크릿

**웹훅 URL · 이메일 계정 비밀번호는 설정 파일에 넣지 않는다.** Alertmanager는 환경 변수를 치환하지 않고 **파일 참조만 지원한다**(`api_url_file` · `smtp_auth_password_file`). 그 파일을 어디에 두고 어떻게 놓는지는 시크릿 주입 방식을 따른다 — **미확정이며 시스템 구성서가 확정 시점과 기록처를 정했다.** 여기서 정하지 않는다.

대시보드 화면의 기본 인증은 Nginx 쪽이고 이 에이전트의 대상이 아니다.

## 4. 검증한다

**문법 → 동작 → 기동** 순서다. 문법만 보고 끝내지 않는다. **명령은 커밋 규약의 확인 명령 표를 따른다.** 여기에 옮겨 적지 않는다.

| 단계 | 대상 | 통과 |
| --- | --- | --- |
| 문법 | 스크레이프 설정 · 규칙 · 라우팅 · 로그 수집 · 로그 저장 · Compose | 오류 0 |
| **동작** | 알림 규칙 — 규칙마다 **발화하는 경우 · 발화하지 않는 경우 · 지속 시간을 채우기 전에는 발화하지 않는 경우** | 보류하지 않은 규칙 전부 통과 |
| 기동 | 로컬 Compose로 기동 | **로컬에 존재하는 대상**은 전부 up. 운영 전용 대상(DB 노드 exporter)은 로컬에서 볼 수 없으므로 문법까지만 |
| 기동 | 대시보드 프로비저닝 | 보류한 패널을 제외하고 전부 로드, 패널 오류 없음 |
| 기동 | 규칙 API | 보류하지 않은 규칙이 전부 올라옴 |

**규칙 동작 시험이 핵심이다.** 문법 검사는 임계를 잘못 옮겨 적어도 통과한다. 규칙마다 시험 케이스를 두어 문서의 조건과 지속 시간이 그대로 구현됐는지 본다. 시험 파일은 규칙과 같은 변경 단위다.

로컬 기동은 재시작해도 된다. **재시작을 쓰지 않는다는 규칙은 서버의 반영 절차에 대한 것이다.**

## 5. 알린다

| 항목 | 내용 |
| --- | --- |
| 검증 결과 | 4장 표 그대로. 확인 명령의 결과는 **커밋 body에 들어간다** |
| 보류한 것 | 미확정 때문에 만들지 않은 규칙 · 패널과 그 이유 |
| 산출되지 않는 지표 | 문서의 어느 행이 걸리는가 |
| 규약 제안 | 문서에 없어 정한 것 |
| 문서에 제안할 것 | 조치 열 · 접근 통제 표 · 규칙 개수 · 반영 절차의 파일명 |
| 서버 반영 | **하지 않았다.** 반영과 확인은 운영 작업이다 |

## 하지 않는다

- **임계값 · 주기 · 보존 · 채널을 정하지 않는다.** 문서의 값을 옮긴다. 다르게 하고 싶으면 문서를 먼저 고친다.
- **문서가 지정한 지표가 없을 때 대체 식을 만들지 않는다.** 보류하고 알린다.
- **서버에 반영하지 않는다.** 설정 파일을 서버로 옮기고 리로드하고 규칙 API로 확인하는 것은 운영 작업이다.
- **애플리케이션 지표를 만들지 않는다.** 커스텀 지표는 백엔드 코드다. 여기서는 그것을 **수집**한다. 카탈로그에 없는 지표는 수집 대상으로 넣지 않고 문서에 제안한다.
- **외부 감시 서비스를 설정하지 않는다.** 콘솔 조작이고 본인이 한다.
- **시크릿 값을 설정 파일에 넣지 않는다.**
- **커밋하지 않는다.** 커밋은 별도 단계이며 `git-check`를 거친다.
