# traffic-builder

**트래픽 정의서를 k6 코드로 옮긴다.** 문서가 정한 값은 그대로 구현하고, **문서에 없는 값은 정하지 않고 미확정으로 남긴다.** 구현이 문서와 같은지 검증까지 한다.

디렉터리 구성과 워크플로 입력은 시험 계획서가, 엔드포인트의 경로·응답 형태는 API 명세가 갖는다. **본 문서는 순서와 경계만 정한다.**

## 순서

```
1. 전제를 본다           명세에 엔드포인트가 있는가 · 더미 데이터가 있는가
        │
        ├── 명세에 없는 엔드포인트 ──→ 멈춘다. 명세를 먼저 고친다
        │
2. 공유 모듈             문서가 공유하라고 지정한 것
        │
3. 프로파일 스크립트     스크립트 대응 표대로. 예비 측정에 쓰는 것부터
        │
4. 토큰 풀               인증 엔드포인트가 조합에 들어올 때
        │
5. 검증                  스크립트가 문서와 같은가. 성능이 아니다
        │
        ├── 명백히 어긋난다 ──→ 구현을 고친다. 문서의 값은 건드리지 않는다
        │
6. 알린다                검증 결과 · 미확정으로 남긴 것 · 문서에 제안할 것
```

**대상이 운영 환경이면 즉시 멈춘다.** 5단계는 실제로 k6를 실행한다.

## 1. 전제를 본다

- **요청 조합의 모든 엔드포인트가 API 명세에 있는가.** 경로·메서드·응답 형태를 명세에서 읽는다. 없는 경로를 추측해 만들지 않는다.
- **더미 데이터가 있는가.** 트래픽 정의서의 데이터 전제를 본다. 없으면 검증이 성립하지 않으므로 알린다. **더미 데이터를 만드는 것은 여기가 아니다.**
- 아직 없는 기능의 엔드포인트는 조합에서 빼고 **뺐다는 사실을 스크립트에 남긴다.** 예비 측정의 축소 조합이 이 경우다. **축소 후의 비중 재배분은 문서에 없다 — 미확정으로 표기하고 어떻게 배분했는지 적는다.**

## 2. 공유 모듈

**트래픽 정의서의 스크립트 대응 절이 공유 모듈로 지정한 항목**을 하나의 모듈에 두고 모든 스크립트가 import한다. 조합을 바꿀 때 한 곳만 수정하기 위해서다.

- **비중은 문서의 표를 그대로 옮긴다.** 반올림하거나 묶지 않는다.
- **여정 규칙을 구현한다.** 지도 응답에서 `propertyId`를 뽑아 상세·위험도로 이어간다. 고정 ID 목록은 여정을 끊고, 같은 매물만 조회하면 캐시 적중률이 실제보다 높아진다 — 후자는 문서의 오염 요인이다.
- **응답 검증은 응답 형태에 맞춘다.** 목록 응답은 문서가 정한 대로 배열 길이를 보고, 단건·쓰기·토큰 갱신은 명세의 응답 형태로 본다.
- **요청마다 엔드포인트와 단계를 태그로 남긴다.** 비중 집계와 워밍업 제외가 태그로 이뤄진다. 태그가 없으면 3.4절의 「각 단계 첫 60초 제외」를 실행할 수단이 없다.
- **`thresholds`로 판정하지 않는다.** 포화점 조건을 스크립트에 넣어 자동 실패시키면 시험 계획서가 본인에게 둔 판정을 스크립트가 대신하게 된다.

## 3. 프로파일 스크립트

**프로파일과 파일의 대응은 트래픽 정의서의 스크립트 대응 표를 따른다.** 표대로 여러 프로파일이 한 파일을 쓰는 경우가 있고, 그때 다른 것은 선행 조치뿐이다.

**「즉석에서 변형하지 않는다」는 인가량·조합·단계를 실행 중에 바꾸지 말라는 것이다. 문서가 입력으로 정한 것은 받는다.**

| 입력 | 근거 |
| --- | --- |
| 지속 시간 | 시험 계획서 워크플로 입력 `duration`. T3는 「시험 길이에 맞춤」이라 고정값이 없다 |
| SSE 동시 연결 수 | 「인가 RPS × 10」이라 프로파일마다 다르다. 호출하는 쪽이 넘긴다 |
| 예비 측정의 T2 상한 | 「50 RPS까지」인데 T2 스크립트는 하나다. **어떻게 자를지는 문서에 없다 — 미확정** |

인가량과 단계 값 자체는 입력으로 받지 않는다.

| 제작 순서 | 이유 |
| --- | --- |
| 예비 측정이 쓰는 프로파일 | 트래픽 정의서 순서 표의 1번 |
| 장애 주입 배경 부하 프로파일 | 하네스가 호출한다 |
| 나머지 | |
| SSE 연결 스크립트 | 붙을 엔드포인트와 팬아웃이 개발 마지막 구간에 온다. 그 전에는 검증할 대상이 없다 |

- **executor는 표가 정한 것을 쓴다.** 이유가 문서에 있다.
- **`maxVUs` 기준은 문서에 있고 값은 없다.** 미확정으로 두고 첫 실측에서 정한다.
- 선행 조치(캐시 비움 · 배치 기동 · 배포)는 **스크립트 안에 넣지 않는다.** 표가 「+ 선행」으로 분리해 적었고, 실행하는 쪽이 순서를 지킨다.

## 4. 토큰 풀

문서가 정한 개수를 사전 발급해 파일로 둔다. **인증이 필요한 엔드포인트가 조합에 들어올 때 필요하다.** 예비 측정의 축소 조합은 공개 조회만이라 필요 없다.

- 생성 스크립트를 함께 둔다. 이름은 시험 계획서의 트리에 없다 — **미확정.**
- **토큰 파일은 커밋하지 않는다.** 자격 증명이고, 자격 증명 커밋은 훅이 막는다. 생성 스크립트만 커밋한다.
- 토큰을 발급하려면 시험 계정이 있어야 한다. **데이터 전제에 항목이 없다 — 제안 대상.**
- **토큰 회전과 풀 크기의 관계가 문서에 없다.** 토큰 갱신이 조합에 있고 회전을 포함하므로, `maxVUs`가 풀 크기를 넘어 VU가 토큰을 공유하면 한쪽의 갱신이 다른 쪽의 토큰을 무효화한다. **구현으로 임의 해결하지 않고 알린다.**

## 5. 검증

**스크립트가 문서와 같은지를 본다. 성능을 보는 것이 아니다.** 로컬에서 낮은 인가량으로 짧게 돈다.

| 확인 | 방법 | 통과 |
| --- | --- | --- |
| 모든 엔드포인트가 정상 응답한다 | 1 VU 스모크 | 명세의 응답 형태와 같다 |
| 실현된 비중 | 태그별 건수 집계표를 정의 옆에 놓는다 | **본인이 본다.** 순서가 뒤바뀌었거나 0인 항목이 있으면 에이전트가 고친다 |
| 여정 규칙이 동작한다 | 상세·위험도 요청의 404 건수 | 0 |
| 스크립트가 인가량을 낸다 | 검증에 쓴 인가량에서 `dropped_iterations` | 0. **검증에 쓴 인가량과 시간을 함께 적는다** |
| executor가 표와 같다 | 스크립트 옵션 | 전부 일치 |

목표 인가량에서의 `dropped_iterations`는 측정 단계의 일이다. 여기서 확인한 것은 「이 인가량에서 0이었다」까지다.

**확인하지 못한 것은 못 했다고 적는다.** 더미 데이터 전에는 비중과 여정을, SSE 엔드포인트 전에는 SSE를 확인할 수 없다. SSE의 두 인스턴스 분산은 측정 단계에서 지표로 본다.

## 6. 알린다

| 항목 | 내용 |
| --- | --- |
| 검증 결과 | 5장 표 그대로. `dropped_iterations`는 인가량·시간과 함께 — 커밋 body에 들어간다 |
| 확인하지 못한 것 | 이유와 함께 |
| 미확정으로 남긴 것 | 축소 조합 비중 · T2 상한 자르기 · `maxVUs` · 생성 스크립트 이름 |
| 문서에 제안할 것 | 시험 계정 전제 · 토큰 회전과 풀 크기 · 트리에 없는 파일 |

문서를 직접 고치지 않는다. 제안한다.

## 하지 않는다

- **문서에 없는 값을 정하지 않는다.** 미확정으로 남기고 알린다.
- **문서에 있는 값을 바꾸지 않는다.** 바꾸고 싶으면 문서를 먼저 고친다. 그 절차는 루트 `CLAUDE.md`가 정한다.
- **시험을 실행하지 않는다.** 5단계의 짧은 실행은 스크립트 검증이고 측정이 아니다.
- **장애 주입 스크립트·하네스·수집기를 만들지 않는다.** `load/` 밖은 범위가 아니다.
- **워크플로를 만들지 않는다.** 스크립트가 받는 입력 이름은 시험 계획서의 워크플로 입력과 맞춘다.
- **더미 데이터를 만들지 않는다.** 전제로 확인만 한다.
- **커밋하지 않는다.** 커밋은 별도 단계이며 `git-check`를 거친다.
