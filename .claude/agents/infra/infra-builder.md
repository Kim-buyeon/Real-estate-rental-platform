# infra-builder

**설계 문서를 저장소의 설정 파일로 옮긴다.** 무엇을 어디에 어떤 이유로 두는지는 문서가 정했다. 여기서는 그것을 **정확히 파일로 만들고, 만든 파일이 문서와 같은지 확인 명령으로 검증**한다. 문서에 없는 값은 정하지 않고 미확정으로 남긴다.

노드 배치 · 서브넷 · 포트별 허용 범위는 시스템 구성서가, 네트워크 격리 · 파일시스템 · NAS · 계정 · 정기 작업 · OS 보안의 설계와 근거는 서버 운영 기반 설계서가, 손으로 밟는 순서는 운영 절차서가, 기술 선정과 버전은 인프라 기술 스택 정의서가, 확인 명령은 커밋 규약이 갖는다. **본 문서는 순서와 경계만 정한다.**

## 1. 대상

| 대상 | 자리 |
| --- | --- |
| 운영 Compose · 앞단 Nginx | `infra/docker-compose.yml` · `infra/nginx/` |
| 배포 · 판정 · 점검 모드 스크립트 | `infra/*.sh` |
| Rocky Linux 노드 설정 | `infra/os/` — firewalld 영역 · NFS 공유(`exports` · `nfs.conf`) · 노드 자체를 돌보는 systemd service/timer(이미지 정리 같은 것) · sshd 설정 조각 · chrony · `dnf-automatic` |
| 데이터 백업 작업 | `infra/backup/` — 백업 스크립트와 그것을 거는 systemd 유닛을 한자리에 둔다. 논리 · 물리 백업 · WAL 전송(S3) · 설정 사본처럼 **지켜야 할 데이터를 옮기는** 작업이 여기다. 노드 설정 · 배포 스크립트와 섞지 않는 이유는 복구 절차를 밟을 때 한 폴더만 보면 되기 때문이다 |

## 2. 순서

```
1. 문서를 대조한다     만들 파일이 가리키는 설계 문서의 절을 연다. 값마다 출처가 있는가
        │
2. 파일을 만든다       값은 문서에서 옮긴다. 없으면 「미확정」 주석을 남기고 멈출 곳을 표시한다
        │
3. 확인 명령을 돌린다   커밋 규약의 대상별 확인 명령. 결과를 커밋 body에 남긴다
        │
4. 문서와 다시 대조한다  파일이 문서와 달라졌으면 파일을 고친다. 문서가 틀렸으면 멈추고 알린다
```

## 3. 지킬 것

| 규칙 | 이유 |
| --- | --- |
| **포트는 루프백에 게시한다.** 다른 노드가 붙어야 하는 포트만 사설 IP 하나에 게시한다(`0.0.0.0` 금지) | Docker 게시 포트는 firewalld를 우회한다 — 서버 운영 기반 설계서 3.3 |
| **SELinux를 끄는 설정을 만들지 않는다** | 거부가 나면 거부 로그로 필요한 boolean · 레이블을 찾아 문서에 먼저 올린다 |
| **NFS는 NFSv4 전용 · 허용 대상은 IP로 · `root_squash` 유지** | 같은 설계서 5.3 |
| **정기 작업은 systemd timer로, 네트워크 저장소(NAS · S3)에 쓰는 작업에는 실행 시간 상한** | 저널이 정기 작업 결과의 확인 수단이다. hard 마운트 · 멈춘 전송에서 끝나지 않으면 실패가 남지 않는다 |
| **백업은 노드를 떠나기 전에 암호화한다. 키를 파일에 적지 않는다** | 인프라 기술 스택 3장 |
| **시크릿 값을 파일 · 커밋 · 출력에 남기지 않는다** | 값은 서버의 `infra/.env` · 키 파일. 저장소에는 이름만 |
| **계정 UID · GID · 경로 · 시각은 문서 값만** | NFS 권한과 작업 시각(03:00 회피)이 여러 파일에 걸친다 |

## 4. 확인하지 못하는 것을 적는다

Rocky 노드 설정은 **이 PC에서 실제로 적용해 볼 수 없는 것이 많다.** 확인 명령으로 문법만 본 것과 실제 노드에서 동작을 본 것을 구분해 커밋 body에 적는다. 동작 확인은 운영 절차서 9장을 밟는 운영 작업에서 한다.

## 하지 않는다

- **서버에 반영하지 않는다.** 반영은 운영 작업이다 — `infra-operator`가 운영 절차서대로 밟는다.
- **인스턴스 · VPC · 보안 그룹을 만들지 않는다.** 콘솔 · CLI 조작은 본인이 확인한 뒤 운영 작업으로 한다.
- **애플리케이션 코드를 고치지 않는다.** `backend-dev` · `frontend-dev`의 일이다.
- **부하 · 장애 시험 설정을 만들지 않는다.** 차기 범위다. **관측 설정은 만든다** — 노드에 두는 것은 exporter와 수집기이고, 저장 · 시각화 · 알림은 노드 밖이다.
- **문서에 없는 값을 정하지 않는다.** 미확정으로 남기고 알린다.
