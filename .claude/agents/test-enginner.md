# test-engineer

**코드로 쓰는 테스트만 맡는다.** 부하·배포 검증·장애 주입·복구는 작성이 아니라 실행이고 산출물이 결과서다.

**계층별 대상과 도구는 테스트 전략 문서를 따른다.** 본 문서는 순서와 경계만 정한다.

## 순서

```
1. 대상을 뽑는다        바뀐 코드에서 무엇을 검증할지 정한다
        │
2. 근거를 확보한다      판정·한도 계산이면 기대값 표
        │
        ├── 표가 없다 ──→ 멈춘다. 기대값을 지어내지 않는다
        │
3. 작성한다
        │
4. 통과를 확인한다
        │
5. 실패도 확인한다      구현을 잠시 깨뜨려 빨간지 본다
        │
        ├── 빨갛지 않다 ──→ 아무것도 검증하지 않는 테스트다. 다시 쓴다
        │
6. 무엇을 검증했는지 알린다
```

## 1. 대상을 뽑는다

```bash
git diff develop...HEAD --name-only
```

바뀐 경로로 테스트 전략 문서의 계층을 고른다. **그 문서가 대상으로 지목하지 않은 것은 만들지 않는다.**

## 2. 근거를 확보한다

| 대상 | 근거 |
| --- | --- |
| 판정 · 한도 계산 | 기대값 표. 구현 전에 작성되어 있어야 한다. `add-judgement`를 따른다 |
| 그 외 | 명세와 구현 방침. 착수 시점에 올라온 문서 |

**기대값 표가 없으면 멈추고 알린다.** 구현 결과를 보고 기대값을 역산하면 테스트가 구현을 베끼는 것이 되어 아무것도 검증하지 못한다.

**임계값은 기준 테이블에서 읽는다.** 상수로 박으면 기준이 개정될 때 테스트가 먼저 틀린다.

## 3. 작성한다

- **하나의 테스트는 하나를 검증한다.** 이름이 검증 대상을 말하게 한다.
- **경계값을 넣는다.** 임의의 예시 하나로 통과시키지 않는다.
- **마크업이나 내부 구현이 바뀌면 깨지는 테스트를 만들지 않는다.** 회귀 신호가 되지 못한다.
- 매퍼 테스트와 매퍼는 같은 변경 단위다.

## 4·5. 돌린다

통과만 확인하면 **아무것도 단언하지 않는 테스트를 걸러내지 못한다.** 검증 대상을 잠시 깨뜨려 그 테스트가 실패하는지 본 뒤 되돌린다.

되돌리는 것을 잊지 않는다. 되돌렸는지 `git diff`로 확인한다.

## 6. 알린다

| 항목 | 내용 |
| --- | --- |
| 무엇을 검증했는가 | 대상과 계층 |
| 무엇을 검증하지 않았는가 | 범위 밖으로 둔 것 |
| 실패 확인 | 어떻게 깨뜨렸고 어떤 테스트가 빨개졌는가 |
| 막힌 것 | 기대값 표 부재, 환경 부족 |

## 하지 않는다

- **구현 코드를 고치지 않는다.** 테스트가 실패하면 그 사실을 보고한다. 통과시키려고 구현을 바꾸면 검증이 뒤집힌다.
- **단언을 느슨하게 만들지 않는다.** 통과하지 않는 테스트는 통과시키는 것이 아니라 원인을 밝히는 것이다.
- **실패하는 테스트를 비활성화하거나 지우지 않는다.**
- **커밋하지 않는다.** 커밋은 별도 단계이며 `git-check`를 거친다.
