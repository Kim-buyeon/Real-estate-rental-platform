# frontend-dev

`frontend/` 하위 코드를 작성한다. **폴더 구조와 작성 규칙은 `frontend/CLAUDE.md`를 따른다.** 본 문서는 순서와 경계만 정한다.

## 작업 순서

화면 하나를 구현할 때의 순서다. **아래에서 위로 거슬러 올라가지 않는다.**

1. **명세 확인** — 대상 엔드포인트의 경로·파라미터·응답 예시와, 지도 화면이면 매물 API 명세 1.4절의 「탐색 동작과 호출 시점」 표를 확인한다. **명세에 없는 필드를 만들지 않고, 명세의 필드명을 바꾸지 않는다.** 응답 봉투(`success` · `data` · `error`)는 공통 규약대로 한 곳에서 벗긴다.
2. **타입** — 응답 예시에서 타입을 쓴다. 열거값은 명세의 문자열 그대로 유니언 타입으로 둔다. 표시 문구는 열거값에 붙인 매핑이 갖는다 — 조건 분기로 변환하지 않는다.
3. **쿼리 훅** — 쿼리 키는 팩토리에 등록하고 거기서만 만든다. 요청을 바꾸는 것(필터 · 표시 영역 좌표 · 커서)은 전부 키에 들어간다. 관심 매물 ↔ 매물, 위험도 ↔ 매물의 무효화 연쇄는 팩토리의 상위 키로 건다.
4. **컴포넌트** — 화면은 조합만 하고, 데이터는 훅이, 표현은 하위 컴포넌트가 갖는다. 색 · 간격 · 반경 · 타이포는 **토큰 변수로만** 쓴다. hex와 px를 직접 적지 않는다. 토큰 목록은 디자인 토큰 정의서, 섹션 순서 · 그리드 · 여백은 그 문서와 짝인 레이아웃 맵을 따른다.
5. **지도** — `kakao-map` 스킬의 표를 따른다. 단계별 호출 · 이벤트 · 재조회 시점 · 표시 요소가 거기 있다.
6. **검증** — 타입 검사, 빌드, 테스트를 순서대로 돌린다. 화면을 열어 명세의 「탐색 동작과 호출 시점」 표대로 요청이 나가는지 네트워크 탭으로 확인한다 — hover에는 요청이 없어야 하고, 지도 이동 한 번에 마커 요청은 한 번이어야 한다.

### 순서가 달라지는 경우

- **`frontend/CLAUDE.md`가 아직 없으면** 화면 코드를 쓰지 않고 그 문서를 먼저 만드는 작업임을 알린다. 규칙 없이 첫 컴포넌트가 작성되면 그 뒤가 전부 그것을 따른다 — 공통을 기능보다 먼저 만드는 작업 흐름의 원칙과 같다.
- **디자인 토큰 정의서가 아직 없으면** 값을 화면에 흩지 않고 토큰 파일 하나에 모아 쓰고, 그 사실을 보고한다. 정의서가 생기면 그 파일을 정의서에 맞춘다.
- **디자인 토큰 정의서가 있는데 거기 없는 색 · 컴포넌트가 필요하면** 만들지 않고 멈춘다. 토큰 추가는 그 문서의 작업이고, 승인 뒤에 반영된다.
- **명세와 백엔드 응답이 다르면** 프론트에서 맞추지 않는다. 어느 쪽이 맞는지 알리고 멈춘다.
- **알림 수신(SSE)을 건드리면** 연결은 애플리케이션 최상위 한 곳이다. 화면에서 `EventSource`를 열지 않는다. 재연결 뒤 목록을 재조회하는 규칙은 알림 전달 문서를 따른다.
- **테스트 대상이면** `test-engineer`가 붙는다. 대상은 SSE 단일 연결 · 재연결과 쿼리 무효화 연쇄다. 화면 렌더링 전반은 대상이 아니다 — 테스트 전략 문서.

## 경계

- **필터는 지도 단계 · 상세 패널과 독립된 상태다.** 단계를 오가거나 상세를 열어도 필터가 바뀌지 않는다. 자치구로 되돌아갈 때 필터가 초기화되는 것이 이슈 가이드가 예로 든 버그다.
- **상세는 화면 이동이 아니라 지도 옆 패널이다.** 지도의 위치 · 확대 수준 · 필터 상태를 유지한다 — 매물 API 명세.
- **화면에서 판정하지 않는다.** 위험 등급 · 전세가율 · 대출 한도는 서버 값을 표시만 한다. 화면에서 다시 계산하면 두 값이 어긋날 때 어느 쪽이 맞는지 알 수 없다.
- **서버 값을 HTML 문자열로 이어붙이지 않는다.** `dangerouslySetInnerHTML`은 쓰지 않는다. 지도 오버레이의 `content`도 문자열이 아니라 엘리먼트로 만든다 — `kakao-map` 스킬.
- **키는 코드에 적지 않는다.** 카카오 JavaScript 키는 `.env`에서 읽는다. REST API 키는 서버 것이며 프론트에서 쓰지 않는다.

## 하지 않는다

- **명세에 없는 경로 · 필드 · 열거값을 만들지 않는다.** 필요하면 명세를 먼저 고치고 그 사실을 보고한다.
- **`backend/` 하위를 건드리지 않는다.** 백엔드 응답이 틀렸으면 알린다.
- **정의서가 있는데 그 밖의 색 · 폰트 · 간격을 쓰지 않는다.** 더 예뻐 보여도 쓰지 않는다.
- **커밋하지 않는다.** 커밋은 별도 단계이며 `git-check`를 거친다.
- **차기 범위 화면에 착수하지 않는다.** 시세 추이 차트 · 상환 시뮬레이션 · 상담이다. 범위 밖이면 그 사실을 알리고 멈춘다.
- **관리자 화면은 만들지 않는다.** ADMIN-01은 1단계 기능이지만 시드 적재와 API까지다 — 로드맵. 차기 범위가 아니라 「화면을 두지 않는 1단계 기능」이므로 그렇게 알린다.
- **동결 이후 화면 작업을 하지 않는다.** 날짜는 로드맵이 정한다. 요청이 오면 동결 뒤임을 알리고 멈춘다.
