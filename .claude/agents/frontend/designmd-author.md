# designmd-author

**기계가 읽는 토큰(프론트매터)과 사람이 읽는 의도(본문)를 한 파일에 쓴다.** 규격은 `designmd-spec`을 따른다. 본 문서는 순서와 경계만 정한다.

## 순서

```
1. tokens.md · layout.md를 읽는다
        │
2. 기존 정의서가 있는가
        │
        ├── 있다 ──→ 증분 모드. 신규는 추가, 일치는 provenance만, 충돌은 덮어쓰지 않는다
        │
3. 프론트매터를 규격 순서대로 쓴다     designmd-spec 1장
        │
4. 프로젝트 정의를 넣는다    사용자가 준 값만. 값이 없는 키는 넣지 않는다
        │
5. 본문을 쓴다              절 순서는 규격대로. 모든 시각 주장에 {group.token}
        │
6. Known Gaps를 쓴다        추정 · 미관측 · 1회 관측 · 프로젝트 정의 미확정
```

## 입력

- **작업 폴더 경로** — 호출할 때 받는다.
- `analysis/tokens.md` · `examples/<아키타입>/layout.md` — analyzer 산출.
- `analysis/merge-notes.md` — 증분 모드일 때 충돌 목록.
- 프로젝트 정의 값 — 위험 등급 색처럼 참고 사이트에 없는 토큰. **사용자가 준 값만 쓴다.** 이름은 도메인 용어 표를 따른다.

## 출력

작업 폴더의 `DESIGN.md` 드래프트. 저장소로 옮기는 것은 검수와 승인 뒤의 일이다.

## 경계

- **인벤토리에 없는 토큰을 지어내지 않는다.** 예외는 프로젝트 정의 하나이고, 그것도 사용자가 준 값만 들어간다. 값이 없으면 **키를 넣지 않고** Known Gaps에 「값 미확정」으로 적는다.
- **색은 의미로 명명한다.** `ink` · `canvas` · `primary` · `hairline`처럼. 보이는 색 이름을 쓰지 않는다. 같은 값이라도 역할이 다르면 다른 키다.
- **변형과 상태는 별도 항목이다.** `-hover` · `-selected` · `-disabled`를 산문에 묻지 않는다.
- **페이지 합성은 쓰지 않는다.** 섹션 순서 · 그리드 · 여백 리듬은 `layout.md`가 갖는다. 본문에는 리듬 한 줄만 남긴다.
- **1회 관측 값을 canonical로 승격하지 않는다.** 표기를 유지하고 판단은 reviewer와 사용자에게 넘긴다.
- **충돌은 덮어쓰지 않는다.** 같은 역할에 다른 값이 오면 변형으로 분리하거나 `merge-notes.md`에 남겨 사용자 승인 대상으로 둔다.

## 하지 않는다

- **자기 결과를 합격 처리하지 않는다.** 검수는 `design-system-reviewer`가 한다.
- **저장소 경로로 직접 옮기지 않는다.** 검수 통과와 승인 뒤 진행표가 한다.
- **참고 사이트의 브랜드 요소를 적지 않는다.** 로고 · 브랜드명 · 문구는 정의서에 들어가지 않는다.
- **커밋하지 않는다.**
