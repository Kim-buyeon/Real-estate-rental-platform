## 1. 데이터 적재 전략

외부에서 가져오는 데이터를 미리 저장할 것인지 요청 시점에 조회할 것인지를 구분한다. 기준은 조회 범위다. 화면이 여러 건을 한 번에 보여주는 데이터는 미리 적재하고, 특정 대상 하나를 분석할 때만 필요한 데이터는 요청 시점에 조회하고 캐싱한다.
지도에서 자치구별 매물 수를 표시하는 화면에서 매번 외부 API를 호출할 수는 없다. 반대로 모든 매물의 등기부를 미리 확보하는 것도 비용상 불가능하다. 두 방식이 함께 필요한 이유다.

### 1.1 사전 적재 대상

| 대상 | 출처 | 적재 방식 |
| --- | --- | --- |
| 매물 | 국토교통부 전월세 실거래가 | 초기 1회 전체 수집 후 정기 갱신. 이 데이터가 없으면 서비스가 성립하지 않는다 |
| 지역 시세 통계 | 실거래가 집계 | 배치가 사전 집계해 REGION_STATS에 저장한다. 요청 시점에 원본을 집계하지 않는다 |
| 대출 상품 | 한국주택금융공사 전세자금대출 고객 특성별 금리(공공데이터포털 15082044) — 은행별 가중평균 금리 | 월 1회 갱신. API 행이 없으면 시드 행. 금감원 비교공시는 상품 추천(LOAN-03, 차기)으로 옮긴다 |
| 금리 이력 | 한국은행 ECOS | 기준금리는 과거 시계열을 일괄 수집. 상품 금리는 수집 시점 이후만 누적된다 |
| 보증 기준 · 보증료율 | 기관 공시 자료 | 개방 API가 없다. 시드 데이터로 적재하며, 기준 데이터 관리 기능이 구현되면 그 경로로 갱신한다 |
| 대출 규제 수치 | 정책 공시 | 시드 데이터로 적재하며, 기준 데이터 관리 기능이 구현되면 그 경로로 갱신한다 |
| 공통 코드 | — | 시드 마이그레이션 |

### 1.2 요청 시점 조회 대상

| 대상 | 출처 | 처리 |
| --- | --- | --- |
| 등기부등본 | 유료 중계 서비스 (현재 Mock) | 특정 매물 분석 시에만 조회한다. 전체 매물에 대해 미리 확보하는 것은 비용상 불가능하다 |
| 건축물대장 | 국토교통부 건축물대장 | 위반건축물 여부와 용도는 보증보험 판정의 입력이며, 판정은 매물 상세 조회 시점에 수행된다. 목록과 마커에는 사용되지 않으므로 전체 매물에 대해 미리 수집하지 않는다 |

- **예외 — 신규 · 미판정 매물은 갱신 배치가 적재 직후 판정한다(2026-09-30 결정 · #298).** 상세를 열기 전에는 판정이 없어 지도에 등급 없이 보이던 문제를 없애기 위해서다. 이 판정도 등기 · 대장을 뗀다. **등기가 Mock인 동안만 비용이 없다** — 실 등기 연동을 정할 때 이 예외를 다시 정한다(인터넷등기소 열람 수수료 1통 700원 + 중계 요금이 신규 매물마다 붙는다). 이미 판정된 매물의 시세 변경 재분석은 등기 · 대장을 다시 떼지 않는다(1.5) — 대장은 Mock 대장 교체 배치와 사용자 재분석이 맡는다(#328).
- **건축HUB 호출은 일일 상한**(`external.building-ledger.daily-limit` — 값은 설정 파일, 계정 일일 트래픽 10,000 은 사용자 확인 2026-09-30)을 사용자 조회와 배치가 함께 쓴다. 상한에 닿으면 대장 없이 판정한다(확인 불가). real 전환 전에 만든 MOCK 대장은 교체 배치(시각은 플랫폼 설계서 7.2)가 관심 매물 먼저 상한만큼 실대장으로 바꾸거나, 뗄 대장이 없으면 지운다(#311).
- **건축HUB 는 초당 요청 한도도 있다**(2026-09-30 운영에서 `LIMITED_NUMBER_OF_SERVICE_REQUESTS_PER_SECOND_EXCEEDS_ERROR` 확인, 한도 값은 문서에 없음). 슬롯 넷이 Redis 초 단위 카운터(`external.building-ledger.per-second-limit` · `per-second-max-wait`, 값은 설정 파일)를 나눠 쓴다. 제공처의 초당 한도 응답은 장애가 아니라 한도라 서킷 · 재시도가 세지 않고 그 조회는 대장 없이 판정하며, 일일 한도 응답이면 일일 카운터를 상한까지 채운다(#318). 교체 배치는 관심 매물 → MOCK 대장 → 대장 행이 없고 조회 키가 있는 매물 순서로 채운다.
- 등기와 대장은 매물 1건 분석 시 함께 필요하므로 병렬로 호출한다. 순차 호출하면 지연이 합산된다.
- 조회 결과는 캐싱한다. 원본 갱신 주기가 길어 유효 기간을 넉넉히 설정할 수 있다.
- 동일 매물에 대한 중복 조회를 캐시로 차단한다. 호출당 비용이 발생하는 연동이다.

### 1.3 데이터 출처와 인증키

적재·조회 대상 데이터의 출처와 인증에 사용하는 환경 변수다. 인증키는 문서와 저장소에 기록하지 않고 .env에 등록한다. 전체 환경 변수 목록은 저장소 최상위 규칙을 따른다.

| 대상 | 출처 | 환경 변수 |
| --- | --- | --- |
| 전월세 실거래가 | 공공데이터포털 (www.data.go.kr) | DATA_GO_KR_API_KEY |
| 매매 실거래가(아파트 · 오피스텔) — 시세 산출 | 공공데이터포털 (www.data.go.kr) | DATA_GO_KR_API_KEY |
| 건축물대장(건축HUB 건축물대장정보 — 표제부) | 공공데이터포털 (www.data.go.kr) | DATA_GO_KR_API_KEY. 조회 키(시군구 · 법정동 · 번 · 지)는 적재 때 실거래 지번과 주소 정규화 admCd 로 채우고, 기존 매물은 갱신 배치가 채운다 |
| 주소 정규화 · 좌표 | 도로명주소 (business.juso.go.kr)<br>카카오 로컬 (developers.kakao.com) | ADDRESS_API_KEY<br>KAKAO_REST_API_KEY |
| 기준금리 · 시장금리 | 한국은행 ECOS (ecos.bok.or.kr/api) | ECOS_API_KEY |
| HF 전세대출 금리(은행별) | 공공데이터포털 (www.data.go.kr) | DATA_GO_KR_API_KEY |
| 대출 상품 · 금리 (차기 LOAN-03) | 금융상품 통합비교공시 (finlife.fss.or.kr) | FINLIFE_API_KEY |
| 등기부등본 | 개방 API 없음. 유료 중계 서비스 필요 | 미연동 — Mock 어댑터 사용 |

- 실거래가(전월세 · 매매)와 건축물대장은 같은 인증키를 사용하지만 활용 신청은 서비스별로 각각 해야 한다. 2026-09-30 기준 아파트 · 오피스텔 전월세 · 매매, 건축HUB 건축물대장정보 모두 신청 완료(실호출 확인). **이 키는 URL 인코딩된 값이다 — 다시 인코딩하면 「등록되지 않은 서비스키」(코드 30)가 난다.**
- 공공데이터포털은 활용 신청 후 승인까지 시간이 걸린다. 승인 전에는 Mock 데이터로 개발을 진행한다.
- 주소 정규화는 적재 단계에서 수행한다. 등기 주소와 대장 주소의 일치 판정이 정규화된 주소를 전제한다.
- 발급이 지연되거나 불가한 항목은 시드 데이터로 대체하고, 연동 인터페이스는 그대로 유지한다.

### 1.4 적재 절차

- 초기 적재는 서비스 기능이 아니라 개발·운영 준비 작업이다. 스키마 구성 단계에서 수행하며, 매물과 기준 데이터가 없으면 위험도 판정과 대출 계산이 동작하지 않는다.
- 매물 초기 데이터는 실거래가 API에서 일괄 수집해 적재한다. 사용자나 관리자가 매물을 등록하는 경로는 두지 않는다.
- 외부 응답을 그대로 저장하지 않는다. 주소를 정규화하고 좌표를 확보한 뒤 저장한다. 등기 주소와 대장 주소의 일치 판정이 정규화된 주소를 전제한다.
- 적재 실패한 항목은 건너뛰고 기록한다. 일부 실패가 전체 적재를 중단시키지 않는다.
- 동일 매물의 중복 적재는 자연키로 차단한다. 재실행해도 결과가 같아야 한다.
- 적재 시점을 함께 저장한다. 시세는 산출 근거와 기준일을 화면에 표시해야 한다.

### 1.5 갱신 주기

| 대상 | 주기 | 비고 |
| --- | --- | --- |
| 매물 · 시세 | 일 1회 + 기동 뒤 오늘 성공 기록이 없으면 1회 | 실거래가 갱신분을 반영한다. 시세가 실제로 변경된 매물만 재분석 대상으로 표시하며, 값이 동일하면 재분석하지 않는다. 신규 매물과 최신 판정이 없는 매물은 같은 회차에 판정한다(1.2 예외). 신규 매물을 구독 조건과 대조한 알림은 차기 범위다 |
| 등기 변동 점검 | 일 1회 + 기동 뒤 오늘 성공 기록이 없으면 1회 | 관심 매물만 대상으로 한다. 전체 매물을 매일 조회하지 않는다 |
| Mock 대장 교체(PROP-04) | 일 1회 + 기동 뒤 오늘 성공 기록이 없으면 1회 | 건축HUB 일일 상한 안에서만(1.2) |
| 금리 | 일 1회 | 변동이 있을 때만 이력에 추가한다 |
| 지역 시세 통계 | 일 1회 또는 주 1회 | 원본인 실거래가의 갱신 주기를 넘지 않는다 |
| 대출 상품 | 월 1회 + 기동 뒤 기준월 행이 없으면 1회 | 금리가 대출 실행 월 단위로 집계된다. 응답에 기준월 필드가 없어 전달(YYYYMM)을 지정해 부른다 |

- **노드는 작업할 때만 켠다** — 꺼진 날의 예약 배치는 돌지 않으므로, 기동 뒤 오늘(서울) 성공 기록(`batch:last-success:{배치}`)이 없는 배치를 매물 · 시세 → 등기 → Mock 대장 교체 순서로 한 번 돌린다(#313, `batch.startup-catchup.enabled`). 실행 여부는 날짜 락이 가르고, 이 기록은 끝난 회차를 기동 때 다시 시작하지 않게만 한다. **중단된 회차는 다음 기동에서 다시 돈다고 보장하지 않는다** — 노드를 멈추면 날짜 락(만료 23시간)이 풀리지 않을 수 있고, Redis 가 남아 있으면 그날은 「다른 인스턴스가 실행 중」으로 건너뛴다(Redis 영속성은 미확인).
- 갱신 배치는 실패해도 기존 데이터를 훼손하지 않는다. 수집에 성공한 항목만 반영한다.
- 갱신 주기보다 짧은 간격으로 재분석하지 않는다. 원본이 바뀌지 않았다면 결과도 같다.
- 재분석 계기는 세 가지다. 시세 변경, 관심 매물의 등기 변동, 사용자의 직접 요청. 시세는 전세가율·깡통전세·보증한도 산출에 모두 쓰이므로 등기가 그대로여도 등급이 바뀔 수 있다.
- 시세가 바뀐 매물은 `property.is_reanalysis_pending` 으로 표시하고 판정 단계가 DB 에서 커서로 읽는다 — 회차 동안 식별자 목록을 메모리에 들고 있지 않는다. 재분석이 실패하거나 락 경합이면 표시가 남아 다음 회차가 다시 잡는다(#314).
- 재분석은 값이 바뀐 매물 전체를 대상으로 하되, 등급이 변동된 경우의 알림은 관심 매물 등록자에게만 발행한다.
