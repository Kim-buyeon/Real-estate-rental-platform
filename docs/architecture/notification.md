## 1. 알림 전달 구조

### 1.1 서버 측 발송

알림은 두 유형이며 발생 계기가 다르다. 저장 구조와 전달 경로는 공통이다.

| 알림 유형 | 발생 계기 | 전달 | 대상 결정 |
| --- | --- | --- | --- |
| 위험도 변경 | 재분석 시 등급 변동 | 앱 내 목록 + 서버 전송 이벤트 | 관심 매물 등록자 중 해당 유형 수신 설정자 |
| 등기 변동 | 일 1회 점검 배치 | 앱 내 목록 + 서버 전송 이벤트 | 관심 매물 등록자 중 해당 유형 수신 설정자 |

두 유형이 동일한 구조로 저장되고 동일한 경로로 전달된다. 접속 중인 사용자에게는 서버 전송 이벤트로 도착을 알리고, 미접속 사용자는 재접속 시 알림 목록에서 확인한다. 어느 경우든 **알림 목록 조회가 완전한 확인 수단이다.**

적용 원칙

- 알림 생성과 발송을 분리한다. 데이터베이스에 알림 이력을 남기는 것을 성공 기준으로 삼고, 실제 전달은 별도 경로로 처리한다. 발송 실패가 판정 결과나 사용자 요청 처리에 영향을 주지 않는다.
- 이벤트는 **트랜잭션 커밋 이후에 발행한다.** 커밋 전에 발행하면 롤백된 판정의 알림이 나가고, 그 순서를 테스트에서 통제할 수 없다.
- 전달 수단은 인터페이스로 추상화한다. 앱 내 조회와 서버 전송 이벤트를 동일한 발송자 계약으로 다루어, 차기 범위인 웹 푸시가 추가될 때 발송 로직을 수정하지 않는다.
- 중복 발송을 방지한다. 동일 사용자·동일 대상·동일 유형의 알림은 캐시 기반 키로 차단하며, 위험도 재분석이 동시에 실행되는 경우는 분산 락으로 제어한다.
- 실시간 전달 수단은 서버 전송 이벤트로 통일한다. 단방향이며 사용자 입력은 일반 요청으로 처리되므로 양방향 상시 연결을 두지 않는다.
- **이벤트를 인스턴스 간에 전파한다.** 애플리케이션이 두 프로세스로 구동되므로, 클라이언트가 연결된 인스턴스와 이벤트를 발행한 인스턴스가 다를 수 있다. 공유 저장소의 발행·구독 채널로 **전 인스턴스에 브로드캐스트하고, 각 인스턴스가 해당 사용자의 연결을 보유했는지 확인해 전달한다.** 연결 위치를 별도로 저장해 라우팅하지 않는다. 인스턴스가 둘뿐이므로 매핑을 유지하는 비용이 더 크다.
- 이 경로가 없으면 이중화 이후 **알림의 절반이 도달하지 않으며, 단일 인스턴스에서는 그 사실이 드러나지 않는다.**
- **활성 연결 수를 지표로 노출한다.** 연결은 응답이 끝나지 않으므로 누수되어도 오류가 나지 않는다. 노출하지 않으면 연결이 쌓이는 것을 확인할 수단이 없다.
- 발송자 인터페이스에 Mock 구현을 두어, 실제 전달 없이 알림 생성 로직을 검증할 수 있게 한다.

### 1.2 클라이언트 측 수신

서버의 알림 전달 경로에 대응하는 수신부를 정의한다. 수신한 알림은 별도 상태에 축적하지 않고 서버 상태 캐시를 무효화하는 방식으로 처리하여, 화면에 표시되는 데이터의 출처를 하나로 유지한다.

| 서버 전달 경로 | 수신 수단 | 처리 방식 |
| --- | --- | --- |
| 서버 전송 이벤트 | EventSource | 알림 도착 시 알림 목록과 관련 도메인 쿼리를 무효화한다. 위험도 변경 알림이면 해당 매물 쿼리도 함께 무효화한다. 전송 본문은 알림 식별자와 유형으로 한정하고 상세는 목록 조회로 가져온다 |

적용 원칙

- 수신한 알림을 화면 상태에 직접 반영하지 않는다. 서버 상태 캐시를 무효화하여 정식 조회 경로로 데이터를 다시 가져온다. 두 경로에서 온 데이터가 서로 다른 값을 보이는 상황을 방지한다.
- 실시간 연결은 보조 수단으로 둔다. 연결이 끊긴 상태에서도 알림 목록 조회로 확인할 수 있어야 하며, **실시간 전달 실패가 기능 자체의 실패가 되어서는 안 된다.**
- 연결이 끊기면 재연결한다. 배포 중 슬롯 교체와 인스턴스 정지 시 연결이 끊기므로, 재연결 후 목록을 재조회해 그 사이 발생한 알림을 확인한다.
- 단방향 알림 수신 연결은 애플리케이션 전역에 하나만 유지한다. 화면 단위로 연결을 생성하지 않는다.
- 읽음 처리는 목록 조회 경로로 수행한다. 수신 시점이 아니라 **사용자가 알림을 확인한 시점**에 읽음으로 표시하며, 처리 후 목록 쿼리를 무효화한다.
