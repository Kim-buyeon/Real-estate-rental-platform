## 1. 영속성 구조

### 1.1 JPA · MyBatis 역할 분담

경계를 반환 타입으로 나눈다. 엔티티가 필요하면 JPA, 화면에 전달할 데이터가 필요하면 MyBatis다. 조회의 복잡도나 결과 건수로 나누면 회색지대가 생겨 작성 시점마다 판단이 필요해지지만, 반환 타입은 조회 목적이 정해지는 순간 함께 결정되므로 판단 지점이 남지 않는다.

| 구분 | 담당 범위 |
| --- | --- |
| JPA — 엔티티 반환 | 등록·수정·삭제 전체, 변경 대상 엔티티 로딩, 연관 엔티티 탐색, 인증 대상 조회, 슈퍼타입-서브타입 매핑 |
| MyBatis — DTO 반환 | 화면에 전달할 조회 전체. 매물 목록·마커, 자치구 집계, 위험도 판정 결과, 알림 목록, 지역 시세 통계, 선순위채권 합산, 대출 상품 다중 조인, 배치용 대량 조회 |

적용 규칙
- MyBatis 매퍼는 조회 전용으로 한정하고 DTO만 반환한다. 엔티티를 반환하지 않으며, INSERT·UPDATE·DELETE는 JPA를 통해서만 수행하여 변경 경로를 단일화한다.
- JPA로 목록을 조회해 화면에 전달하지 않는다. 엔티티 목록을 가져올 일이 줄어들어 N+1 문제가 구조적으로 발생하지 않으며, 화면에 필요한 컬럼만 조회하므로 전송량도 줄어든다.
- 같은 조회를 두 기술로 중복 구현하지 않는다. 반환 타입이 다르면 용도가 다른 것이므로, 중복 여부는 반환 타입으로 판별한다.
- MyBatis는 영속성 컨텍스트를 우회하므로, 동일 트랜잭션 안에서 JPA로 변경한 데이터를 MyBatis로 조회하면 반영되지 않은 값을 읽을 수 있다. 조회 전 flush를 수행하거나 읽기·쓰기 트랜잭션을 분리한다.
- 매퍼 인터페이스는 도메인 패키지 하위에, XML은 src/main/resources/mapper/<도메인>/ 아래에 배치한다.
- 매퍼는 작성과 동시에 테스트를 작성한다. 컴파일 시점 검증이 없는 대신, 실제 데이터베이스를 사용한 매퍼 테스트로 컬럼명·문법 오류를 차단한다.
- 두 기술 모두 동일 DataSource를 사용하므로 트랜잭션은 Spring이 함께 관리한다. 별도 트랜잭션 매니저를 두지 않는다.

### 1.2 정밀 연산 규칙

전세가율, 깡통전세 판정, LTV·DSR·Stress DSR 한도는 원 단위 오차가 판정 결과를 뒤집을 수 있다. 금액과 이율을 다루는 모든 연산에 BigDecimal을 사용하며 double·float 사용을 금지한다. 나눗셈은 반올림 모드를 명시한다.

### 1.3 위경도 반경 검색 방식

PostGIS·Oracle Spatial 등 공간 확장을 사용하지 않는다. 서울 25개 자치구, 매물 수만 건 규모에서는 (latitude, longitude) 복합 B-tree 인덱스로 충분하며, 검색 조건에 district가 선행 필터로 붙어 후보 집합이 이미 작기 때문이다.
- 애플리케이션에서 반경으로부터 바운딩 박스를 계산해 위경도 BETWEEN 조건으로 1차 필터링한다.
- Haversine 공식으로 정확한 거리를 산출해 반경 조건을 최종 적용하고 거리순 정렬한다.
- DB 벤더 종속 함수를 쓰지 않으므로 테스트 환경 전환이 자유롭고, 향후 데이터가 수십만 건 규모로 늘어날 경우 해당 쿼리 한 곳만 공간 인덱스 방식으로 교체하면 된다.
