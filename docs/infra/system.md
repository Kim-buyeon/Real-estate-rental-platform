## 1. 문서 목적

본 문서는 `docs/features/infra.md`가 정의한 인프라 기능(INF-01 ~ INF-06)이 **실제로 어디에 배치되고, 어떤 목표를 만족해야 하며, 얼마의 비용이 드는지**를 정의한다.

기능이 무엇을 제공하고 왜 필요한지는 `docs/features/infra.md`가 다룬다. 본 문서는 그 기능들이 놓이는 물리적·논리적 구성과 수치 목표만 담는다.

## 2. 논리 구성도

논리 구성도: `docs/infra/system-diagram.png`
APP-01 · DB-01 · DB-02 세 노드의 구성과 상시 경로.

| 노드 | 담긴 것 |
|---|---|
| APP-01 | Nginx, 애플리케이션 두 슬롯, Redis, 관측 스택 |
| DB-01 | PostgreSQL Primary. WAL을 오브젝트 스토리지로 아카이빙 |
| DB-02 | PostgreSQL Standby. 복제만 수신하며 트래픽을 받지 않는다 |
| APP-02 | 부하 생성기. 시험 기간에만 기동하며 애플리케이션과 자원을 나누지 않는다 |

## 3. 노드 구성

| 노드 | 사양 | 구동 대상 | 상시 기동 |
|---|---|---|---|
| APP-01 | 2 vCPU / 4 GB | Nginx, App ×2, Redis, 관측 스택 | 예 |
| DB-01 | 2 vCPU / 2 GB | PostgreSQL Primary | 예 |
| DB-02 | 1 vCPU / 1 GB | PostgreSQL Standby | 예 (복제 수신 전용) |
| APP-02 | 2 vCPU / 4 GB | 부하 생성기 (INF-06) | 아니오. 시험 기간에만 기동 |

**사양은 미확정이다.** 위 값은 초기 배치이며 5주차 부하 시험에서 실측한 뒤 확정한다. 특히 APP-01은 앱 2 프로세스와 관측 스택이 함께 올라가므로 4 GB로 충분한지 확인이 필요하고, DB-02는 승격 시 primary 역할을 감당하는지 확인이 필요하다(`docs/infra/runbook.md` 6.2절).

**저장소 자원 상한**

| 대상 | 설정 |
|---|---|
| PostgreSQL | `shared_buffers`, 최대 커넥션 수 상한 |
| Redis | `maxmemory` 상한과 축출 정책(`maxmemory-policy`). 상한이 없으면 APP-01의 다른 프로세스를 밀어낸다 |

Redis에는 복제도 백업도 두지 않는다. 정지하면 내용이 사라지므로 재생성 가능한 데이터만 보관한다.

APP-01 단일 노드에 두 프로세스를 두는 구성은 노드 자체의 장애에 대응하지 못한다. 비용 제약을 수용한 결과이며, 필요한 시점에 APP-02를 애플리케이션 노드로 전환하고 upstream에 추가하는 것으로 확장한다. **본 설계의 목표는 구성을 완성하는 것이 아니라 확장 지점을 미리 정의하는 것이다.**

부하 생성기를 애플리케이션과 같은 노드에 두면 CPU를 나눠 써 측정이 오염되므로 APP-02에 둔다.

## 4. 네트워크 및 접근 통제

| 구간 | 포트 | 허용 범위 |
|---|---|---|
| 사용자 → Nginx | 443 / 80 | 전체. 80은 443으로 리다이렉트 |
| Nginx → App | 8081 · 8082 | 동일 노드 루프백 |
| App → PostgreSQL | 5432 | APP-01 · APP-02 사설 IP만 |
| App → Redis | 6379 | 동일 노드 루프백. 외부 바인딩 금지 |
| Primary → Standby | 5432 | DB-01 사설 IP만 |
| Prometheus → APP-01 exporter | 9100 · 9113 · 9115 · 9121 · 9187 | APP-01 내부 |
| Prometheus → DB 노드 exporter | 9100 | DB-01 · DB-02 사설 IP만 |
| Promtail → Loki | 3100 | 동일 노드 루프백 |
| 운영자 → 전 노드 | 22 | 공개키 인증만. 비밀번호 인증과 root 로그인은 차단 |
| 운영자 → Grafana | 3000 | Nginx 경유 + 기본 인증. 직접 노출 금지 |

**공개된 포트는 자동 스캔의 대상이 된다.** 비밀번호 인증을 켜두면 대입 시도가 계속되고, Redis는 기본 설정에 인증이 없어 노출 시 즉시 접근된다. 따라서 SSH는 공개키 인증만 허용하고, 데이터 저장소는 인터넷에 노출하지 않는다.

**시크릿 주입 방식은 미확정이다.** DB 비밀번호, 외부 API 키, JWT 서명 키, 백업 복호화 키, Slack 웹훅 URL(채널별 3개), Grafana 기본 인증 계정을 어디에 두고 어떻게 주입할지는 1주차 프로젝트 셋업 시점에 확정하고 `docs/infra/runbook.md` 3장에 기록한다. 현 시점의 방침은 저장소에 커밋하지 않는다는 것뿐이다.

## 5. 가용성 목표

### 5.1 등급별 목표

기능을 중요도에 따라 세 등급으로 나눈다. 모든 기능에 동일한 가용성을 요구하면 비용이 불필요하게 커진다.

등급 구분과 RTO·RPO 체계는 「행정기관 및 공공기관 정보시스템 안정성 고시」(2026.3)의 등급별 복구 목표 체계를 참조했다. 민간 서비스이므로 고시의 적용 대상은 아니며, 목표값도 해당 등급 기준보다 엄격하게 잡았다.

| 등급 | 대상 기능 | 목표 | RTO | RPO | 참조 등급 |
|---|---|---|---|---|---|
| 1등급 | PROP-01 · 02 · 03 · 08, USER-02 | 99.5% / 월 | 30분 | 5분 | A2 (3~12시간) |
| 2등급 | RISK-01, LOAN-01, NOTI-03 | 99.0% / 월 | 2시간 | 15분 | A3 (1~5일) |
| 3등급 | RISK-08 배치 | 95.0% / 월 | 24시간 | 24시간 | A4 (3주) |

**이중화 방식도 등급에 따라 다르다.** 애플리케이션 계층은 두 슬롯이 동시에 요청을 처리하는 **액티브-액티브**이고, 데이터 계층은 standby가 트래픽을 받지 않는 **액티브-스탠바이**다. 후자는 승격이라는 수동 단계를 거치므로 RTO가 분 단위로 잡힌다. 두 계층에 같은 방식을 쓰지 않는 이유는 `docs/decisions.md` D-03에 있다.

99.5%는 월 약 3시간 39분의 허용 중단에 해당한다. 계획된 배포로 인한 중단은 INF-02로 이 시간에서 제외한다.

달성률은 `docs/infra/observability.md` 3장의 요청 지표로 집계한다. 30일 구간의 성공 응답 비율을 `docs/infra/runbook.md` 2장 월 1회 점검에서 확인한다.

```promql
sum(rate(http_server_requests_seconds_count{status!~"5.."}[30d]))
/
sum(rate(http_server_requests_seconds_count[30d]))
```

**RPO 5분은 INF-03(복제)가 아니라 INF-04(WAL 아카이빙 5분 강제 스위치)가 보장한다.** 두 수단의 역할을 혼동하지 않는다.

### 5.2 성능 저하 시 동작 정의

구성 요소가 정지했을 때 서비스가 어디까지 동작해야 하는지를 사전에 정의한다. 정의가 없으면 장애 시 판단이 즉흥적으로 이루어진다.

| 중단 대상 | 동작 가능 | 동작 불가 | 사용자 안내 |
|---|---|---|---|
| Redis | 매물 조회 · 상세 · 위험도 조회 | 로그인 유지, 실시간 알림 | 재로그인 요청 |
| 앱 1대 | 전 기능 | 없음 | 없음 |
| PostgreSQL Standby | 전 기능 | 없음 | 없음. 복제 지연 알림만 |
| PostgreSQL Primary | 없음 | 전 기능 | 점검 페이지 |

## 6. 비용 산정

서울 리전 온디맨드 기준 개략치이며 약정 할인은 반영하지 않았다. **3장의 미확정 사양을 전제로 산정했으므로 사양 확정 시 본 절을 갱신한다.**

| 항목 | 사양 | 월 비용(개략) |
|---|---|---|
| APP-01 | 2 vCPU / 4 GB | 20,000 ~ 25,000원 |
| DB-01 | 2 vCPU / 2 GB | 12,000 ~ 15,000원 |
| DB-02 (standby) | 1 vCPU / 1 GB | 6,000 ~ 8,000원 |
| 블록 스토리지 | 60 GB | 3,000 ~ 4,000원 |
| 오브젝트 스토리지(백업) | 20 GB | 500원 미만 |
| TLS 인증서 | Let's Encrypt | 0원 |
| 도메인 등록 | .com 등 | 연 15,000 ~ 20,000원 (월 환산 약 1,500원) |
| **평시 합계** | | **약 43,500 ~ 54,500원** |
| APP-02 (시험 기간 한정) | 2 vCPU / 4 GB | 일 700 ~ 800원 |

블록 스토리지 60 GB는 DB 데이터가 아니라 OS·컨테이너 이미지, Prometheus 지표 15일 보존, 로그, WAL 아카이브 스테이징이 대부분을 차지한다. 항목별 소요량은 1주차에 스키마 적용과 더미 데이터 적재를 마친 뒤 실측해 확정한다.

**절감 수단**

- 관측 스택(INF-05)을 별도 노드에 두지 않고 APP-01에 함께 구동한다. 지표 보존 15일로 스토리지 억제
- standby를 최소 사양으로 두고 승격 시점에만 사양을 올린다(재기동 필요, RTO +3분)
- 상시 이중화가 불필요한 기간에는 DB-02를 정지하고 백업 기반 복구로 낮춘다
