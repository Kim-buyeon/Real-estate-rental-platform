# 규약

언어와 계층에 무관하게 적용된다. 목적은 하나다. **6개월 뒤에 읽어도 의도가 드러나는 코드.**

언어별 네이밍(Java 클래스·패키지, TypeScript 컴포넌트·훅 등)은 `backend/CLAUDE.md`와 `frontend/CLAUDE.md`를 따른다.

---

## 네이밍

- **열거값은 대문자 스네이크.** 국내 제도 고유 개념은 음차가 아니라 특성을 나타내는 영어로 명명한다. `DEPOSIT_ONLY`(전세) · `MONTHLY_RENT`(월세) · `SEMI_DEPOSIT`(반전세)
- **데이터베이스 테이블·컬럼은 소문자 스네이크.**
- **API 경로는 소문자 하이픈, 자원은 복수형.** 인증 사용자 종속 자원은 `/api/me` 하위.
- **JSON 필드는 소문자 카멜.**

## 도메인 용어

## 코딩 규칙

### 이름이 의도를 말하게

- 무엇을 하는지가 아니라 **무엇을 판단·반환하는지**를 이름에 담는다. `check()` 대신 `isEligibleForGuarantee()`, `getProperty()` 대신 `findPropertyOrThrow()`
- 불리언은 `is`·`has`·`can` 접두를 붙여 조건문에서 문장처럼 읽히게 한다.
- 축약하지 않는다. `propAmt`가 아니라 `propertyAmount`.
- 같은 개념에 같은 이름을 쓴다. 도메인 용어는 위 표를 따른다.

### 매직 넘버를 쓰지 않는다

숫자와 문자열 리터럴에 이름을 붙인다. 무엇을 뜻하는지 코드에서 읽혀야 한다.

```
if (ratio > 80)                       // 80이 무엇인가
if (ratio > CAUTION_DEBT_RATIO)       // 주의 등급 기준
```

정책에 따라 바뀌는 값은 상수가 아니라 설정이나 저장소에서 읽는다.

### 중첩을 줄인다

조건이 맞지 않으면 먼저 빠져나온다. 정상 흐름이 들여쓰기 없이 이어지게 한다.

```
if (property == null) throw ...;
if (!property.hasAnalysis()) throw ...;
// 이후 정상 흐름
```

중첩이 세 단계를 넘으면 분리한다.

### 함수는 한 가지만 한다

- 상위 함수는 흐름만 보이게 하고, 각 단계는 이름 있는 함수로 분리한다.
- 함수 이름과 실제 동작이 어긋나지 않게 한다. 조회 함수가 저장을 하지 않는다.
- 함수가 화면 하나를 넘어가면 분리를 검토한다.

### 주석은 왜만 남긴다

- 코드가 이미 말하는 것을 반복하지 않는다.
- 그렇게 한 이유, 그렇게 하지 않으면 생기는 문제, 참고한 근거를 남긴다.
- 주석으로 설명해야 이해되는 코드라면 이름이나 구조를 먼저 고친다.

```
// 순위번호가 임차인보다 앞서고 현재 유효한 것만 합산한다.
// 말소된 근저당을 포함하면 실제보다 위험하게 판정된다.
```

### 계층 방향을 지킨다

- 참조는 한 방향으로만 흐른다. 하위 계층이 상위 계층을 참조하지 않는다.
- 계층을 건너뛰지 않는다. 중간 계층이 하는 일을 우회해서 직접 호출하지 않는다.
- 순환 참조가 생기면 상위에 조합 계층을 두거나 이벤트로 끊는다.

계층 구성과 도메인 간 접근 규칙은 각 디렉터리의 `CLAUDE.md`를 따른다.

### 파일 안 순서를 고정한다

같은 자리에 같은 것이 있으면 찾는 시간이 줄어든다. **상수 → 상태 → 진입점 → 내부 구현** 순으로 배치한다.

### 미리 만들지 않는다

- 지금 쓰지 않는 확장 지점, 구현이 하나뿐인 인터페이스, 사용처 없는 유틸을 만들지 않는다.
- 필요해지는 시점에 만들면 그때 정확한 형태로 만들 수 있다.
- 중복이 두 번 나타났다고 바로 추상화하지 않는다. **세 번째에 판단한다.**

### 정합을 유지한다

- 서버와 화면이 주고받는 필드명은 API 명세서와 일치시킨다. 어느 한쪽에서 이름을 바꾸지 않는다.
- 열거값 문자열은 서버·화면·문서에서 동일하게 사용한다.
- 표시 문구는 열거형이 갖는다. 값을 조건 분기로 변환하지 않는다.
