# 전월세 부동산 금융 플랫폼 — 서비스 기능 정의서 — 개요

> 기능 색인 · 문서 라우팅
> 1단계 22개 기능 · 6개 영역
>
> ※ **작업 착수 시 어느 문서를 읽어야 하는지를 이 문서에서 판단한다.** 기능 상세는 여기에 두지 않는다.
> 작성 기준일 : 2026년 8월

## 1. 영역과 읽을 문서

작업 대상 기능 ID로 영역을 찾고, 그 행의 문서를 읽는다.

| 영역 | 기능 ID | 기능 정의 | API 명세 | 함께 읽을 문서 |
| --- | --- | --- | --- | --- |
| 회원 | USER-01 · 02 · 03 | `docs/features/user.md` | `docs/api/user.md` | — |
| 매물 | PROP-01 · 02 · 03 · 04 · 05 · 08 | `docs/features/property.md` | `docs/api/property.md` | `docs/architecture/database.md` |
| 위험도 | RISK-01 · 02 · 03 · 04 · 05 · 07 · 08 | `docs/features/risk.md` | `docs/api/risk.md` | **비즈니스 로직 정의** |
| 대출 | LOAN-01 | `docs/features/loan.md` | `docs/api/loan.md` | **비즈니스 로직 정의** |
| 알림 | NOTI-01 · 02 · 03 · 05 | `docs/features/notification.md` | `docs/api/notification.md` | — |
| 관리자 | ADMIN-01 | `docs/features/admin.md` | `docs/api/admin.md` | — |
| 인프라 | INF-01 ~ 06 | `docs/features/infra.md` | `docs/api/infra.md` · `docs/api/observability.md` | `docs/infra/` 해당 문서 |

- **`docs/api/common.md`는 모든 영역에서 함께 읽는다.** 요청·응답 형식과 오류 코드가 거기 있다.
- **인프라는 `docs/api/common.md`를 읽지 않는다.** 공통 규약이 적용되지 않는다.
- **위험도·대출은 비즈니스 로직 문서가 필수다.** 산식과 임계값이 기능 정의에 없다.
- 비즈니스 로직 정의서의 경로는 확정 후 이 표에 채운다. 아키텍처 문서군과는 별개다.

`선행` 열의 기능은 입력을 제공하므로 함께 읽는다. 다른 영역의 기능이면 1장에서 그 영역의 경로를 찾아 함께 연다.

| --- | --- | --- |
| USER-01 | 회원 가입 | — |
| USER-02 | 로그인 · 토큰 갱신 | USER-01 |
| USER-03 | 자격 정보 관리 | USER-01 |
| PROP-01 | 매물 목록 검색 | RISK-01 |
| PROP-02 | 지도 드릴다운 탐색 | PROP-08 · RISK-01 |
| PROP-03 | 매물 상세 조회 | RISK-01 |

- ADMIN-01은 기준 데이터가 시드로 적재되어 있으면 성립한다. 관리 화면 자체는 판정 기능보다 나중에 만들어도 된다.

## 3. 차기 범위

아래 ID는 1단계에 없다. **번호를 재사용하지 않으므로 결번은 차기 범위를 뜻한다.**

| 결번 | 기능 | 1단계에서 확보하는 것 |
| --- | --- | --- |
| CONS 전체 | 대화형 해설과 상담 이력 | 판정 근거를 항목별로 제시 |
| USER-04 | 검색 이력 | — (상담 컨텍스트 제공이 목적이었으므로 함께 제외) |
| USER-01 일부 | 소셜 로그인 제공자 | 이메일 기반 인증 구조 |
| USER-05 | 회원 탈퇴 | 파기 정책은 설계 문서로 남긴다 |
| PROP-06 · 07 | 전환율 계산 | 자치구 집계와 지도 탐색 |
| RISK-06 | 보증 신청기한 계산 | — |
| LOAN-02 ~ 06 | 정책상품 자격, 상품 추천, 상환 시뮬레이션, 대출 계획, 금리 이력 | 규제 계산에 따른 한도 산출 |
| NOTI-04 | 미접속 사용자 웹 푸시 | SSE로 접속 중 사용자 도달 |

차기 범위 기능을 요청받으면 착수하지 않고 범위 밖임을 알린다. **다만 1단계 22개 기능과 인프라 기능(INF-01 ~ 06)이 모두 완료된 뒤라면 착수한다.**

인프라까지 완료를 조건으로 두는 이유는, 남은 시간에 차기 기능을 먼저 손대면 그 시간이 이중화·복구·시험에서 빠지기 때문이다. 기능 몇 개를 더 만드는 것과 검증 축 하나를 잃는 것은 비교 대상이 아니다.
