## 범위

**두 덩어리다.**

| 덩어리 | 무엇 | 왜 |

**본문 구역은 「베껴 적기」가 아니라 「쓸 수 있는 구조의 계측」이다.** 우리 메인 화면의 섹션은 참고 사이트와 다르다. 아래 값은 **자리 · 크기 · 리듬**이고, 무엇을 담을지는 우리가 정한다.

**계측하지 않은 것** — 광고 블록 · 해시태그 칩 줄 · 분양 · 콘텐츠 카드 5열. 우리가 만들지 않는다. 다만 그것들이 차지하던 **폭**이 그리드 계산에 필요한 경우에만 폭을 적었다.

**`map-search` 는 예외로 푸터를 붙이지 않는다** — 뷰포트의 남은 높이를 전부 쓰는 유동 구조이고 참고 사이트도 그 아키타입 5컷 모두에 푸터가 없다 (정의서 7절).

## 반응형 붕괴 — 본문 구역 (제안 · 미관측)

**미관측이다.** `home` 3컷 모두 뷰포트 2520~2554px 의 초광폭 데스크톱이다. 모바일 · 태블릿 컷이 없다.
아래는 승인된 브레이크포인트(모바일 `~767` / 태블릿 `768~1023` / 데스크톱 `1024~`, 컨테이너 max **1200**)에서의 **제안**이며 **계측값이 아니다.** 위 표들과 섞어 읽지 않는다.

### 제안(미관측) — 데스크톱 `1024~`

컨테이너 `max-width: 1200` · 좌우 패딩 24 → 내용 폭 **1152**.

| 구역 | 제안 |
| --- | --- |
| hero | 요소 폭 770 → 컨테이너의 58% = **660**, 높이 **48** 유지. 위 **64** `{spacing.4xl}` / 아래 **24** `{spacing.xl}` |
| 카테고리 카드 | **우 레일을 버린다**(광고는 우리에게 없다) → 카드가 내용 폭 전체. **2장이면 각 566** · **3장이면 각 371** (갭 20). 높이는 고정 200 |
| 매물 그리드 | 4열 유지 · 갭 20. **컬럼 폭은 아래 주의** |
| 섹션 사이 | 64 `{spacing.4xl}` · 제목↔내용 48 `{spacing.3xl}` |

> **주의 — 컬럼 폭이 정의서와 어긋난다.** 정의서 4장은 4컬럼을 **285 · gap 20** 으로 정했고 4×285 + 3×20 = 1200 이다. 이는 **좌우 패딩 0** 을 전제한다. 이 문서의 푸터 구역과 위 제안은 좌우 패딩 24 를 두므로 같은 4열이 (1152 − 60) ÷ 4 = **273** 이 된다. **둘 중 무엇을 정본으로 할지 이 문서가 정하지 않는다** — 정의서 4장이 정할 일이다. 구현은 이 결정을 받고 시작한다.

### 제안(미관측) — 태블릿 `768~1023`

컨테이너 100% · 좌우 패딩 24 → 내용 폭 720~975.

| 구역 | 제안 |
| --- | --- |
| hero | 요소 **전폭** · 높이 48 유지 |
| 카테고리 카드 | **2열**. 3장이면 2 + 1 (마지막 장이 전폭). 갭 20, 높이 고정 해제 |
| 매물 그리드 | 4열 → **2열**. 컬럼 (720 − 20) ÷ 2 = **350** |
| 섹션 사이 | 64 → **48** `{spacing.3xl}` · 제목↔내용 48 → **32** `{spacing.2xl}` |

### 제안(미관측) — 모바일 `~767`

컨테이너 100% · 좌우 패딩 16 `{spacing.md}`.

| 구역 | 제안 |
| --- | --- |
| hero | 요소 **전폭** · 높이 **48** (터치 하한 44 충족) · 위 **32** `{spacing.2xl}` / 아래 **24** `{spacing.xl}` |
| 카테고리 카드 | **1열** · 갭 **12** `{spacing.sm}` · **고정 높이 해제**(내용 높이). 제목 `{typography.heading-3}` 로 한 단 내린다 |
| 매물 그리드 | **1열**. 우리 카드는 썸네일이 없어 글자만 남으므로 2열을 유지하면 줄 말줄임이 과해진다 |
| 줄 피치 | 28 유지. 4줄 구조 유지 |
| 섹션 사이 | **48** `{spacing.3xl}` · 제목↔내용 **24** `{spacing.xl}` · 섹션 제목 `{typography.heading-2}` 유지 |

> 참고 사이트가 모바일에서 카드 몇 열로 접는지, 히어로를 남기는지는 **확인할 수 없다.** 위는 제안이다.

## 반응형 붕괴

**미관측 — 데스크톱 컷만 있음.** 6개 컷 모두 뷰포트 2518~2559px 의 초광폭 데스크톱이다. 모바일·태블릿 푸터 컷이 없다.

아래는 승인된 브레이크포인트(모바일 ~767 / 태블릿 768~1023 / 데스크톱 1024~, 컨테이너 max 1200)에서의 **제안(미관측)** 이다. 계측값이 아니다.

### 제안(미관측) — 데스크톱 1024~

- 컨테이너 1330 → 우리 정의 **`max-width: 1200`** · 좌우 패딩 24
- sitemap 6컬럼 유지 → 컬럼 폭 (1200-48) ÷ 6 = 192
- link-bar 검색 셀 329 · TOP 셀 73 그대로. 좌측 링크와의 빈 공간만 줄어든다

### 제안(미관측) — 태블릿 768~1023

- 컨테이너 100% · 좌우 패딩 24
- sitemap **6컬럼 → 3컬럼 2행**. 컬럼 폭 (768-48) ÷ 3 = 240. 행 사이 40
- link-bar 유지. 검색 셀 329 → 240 으로 축소, TOP 셀 73 유지
- business-info · copyright 그대로

### 제안(미관측) — 모바일 ~767

- 컨테이너 100% · 좌우 패딩 16
- **sitemap 은 접는다.** 6컬럼 → 아코디언 6개(각 높이 52, 구분선 1px `{colors.border}`) 또는 전체 생략. 링크 31px 줄높이 × 최대 5줄 × 6컬럼을 세로로 펼치면 푸터가 과하게 길어진다
- link-bar **2줄로 접는다**
  - 1줄: 정책 링크 4개 (넘치면 2줄 랩, 줄 피치 32)
  - 2줄: 검색 입력 100% (높이 48) — 세로 구분선 제거
  - **TOP 은 셀에서 빼내 화면 우하단 고정 원형 버튼(48)** 으로 전환
- business-info: 줄 피치 20 유지, 글자 13 유지. 소형 버튼 4개는 **2×2 랩** (갭 8)
- 소셜 버튼: 우측 정렬 → **좌측 정렬 · 버튼 줄 아래 24** 로 내린다 (같은 y 유지 불가)
- copyright 그대로
- 구역 2↔3 구분선은 컨테이너 폭 → 좌우 패딩 안쪽 폭
